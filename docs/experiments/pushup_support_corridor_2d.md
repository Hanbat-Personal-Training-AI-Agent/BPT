# Push-up support corridor: isolated core, 2026-10-26

Initial pure-core scope (commit 75652a2): `PushUpSupportCorridor2D.swift` is an independent pure Foundation module with synthetic unit tests. `Config.enabled` defaults to false. It has no callers in CameraPosePreview, no UI/XS/coaching integration, no model changes and no 3D input/output. MotionAGFormer-XS stays untouched. The CalibrationEngineKit source symlink makes the module CPU-testable. Parameters are engineering hypotheses, not tuned or clinically/visually validated limits.

## Proposed integration contract (not wired)

- Use source presentation timestamps in seconds and a single analysis-image coordinate frame. Reset on session/camera/tracker/person identity, image orientation/crop coordinate-frame changes, camera motion/unknown stability, explicit reset, non-increasing PTS or >.15s source gap. The caller must change camera identity when image coordinate transforms change. Fixed-camera status needs external evidence; a manual true flag is not camera-motion detection.
- Provide bodyScale as an independent finite positive body length in the same pixels, not corrected wrist/forearm length. The uncertain corridor uses .06 × min(current scale, acquisition scale), so scale growth cannot enlarge an old anchor. Invalid scale fails closed; no forearm exact-length or target-posture constraint exists.
- A credible wrist requires raw SimCC score ≥.7 (not a probability) **and** three external evidence inputs: observed identity/visibility, neighbor/side/anatomy consistency, and temporal correspondence. These are separate vetoes. The pure module does not compute or validate these signals, and hand detector confidence alone must not set them all true. Neighbor evidence may check broad plausibility/hand duplication, but must never enforce ideal push-up posture or an exact forearm length. Temporal evidence must allow coherent real relocation rather than requiring proximity to the old anchor. No available phone logs establish these booleans as ground truth.
- Credible wrists always pass through byte-for-byte coordinates, including poor posture and locations outside the corridor. An outside observation releases the old support immediately; at least three stable credible samples spanning .12s acquire a new anchor. Low-confidence/unsupported isolated points cannot acquire, move or refresh it.
- An untrusted wrist may be radially bounded around a previously observed stable anchor for at most .35s since the last credible observation. An absent wrist uses the anchor during that interval. This is an explicitly inferred camera-space allowance, not an observed hand position, genuine motion recovery or 3D ground lock. Real hidden movement cannot be reconstructed. After expiry, displayPoint is nil and the anchor is discarded; later uncertain raw values must stay hidden, not return as a solid skeleton.
- Result preserves raw observations, sourcePTS, reason, anchor, inference flag, age and correction magnitude (nil if raw coordinates are absent/nonfinite). Render inferred wrists and connected segments with uncertainty styling; hide the wrist and adjacent segments on nil. Consumers without per-joint visibility must withhold the skeleton when withholdSkeleton is true. Do not allow subsequent smoothing to resurrect hidden/stale points.
- Every inferred/hidden output has assessmentEligible and armAndHandCoachingEligible false. This veto must propagate to elbow-angle/hand-position coaching and any 3D lifting influenced by that wrist. Do not feed inferred points into XS. Existing pose assessment has other required validity gates; true here is only wrist evidence eligibility, not permission to emit any coaching.
- Root-relative 3D remains raw and separate. Moving roots cannot be ground-locked by this API. A future 3D solution requires an established camera/world projection and synchronized root/camera evidence, not copying 2D anchor values into a 3D wrist.

## Separately reviewed opt-in native experiment

The subsequent adapter/native commit adds `PushUpSupportEvidence2D`, CameraPosePreview routing, and renderer styling. Default behavior remains unchanged. `BPT_PUSHUP_SUPPORT_CORRIDOR=1` opts in; it never activates the old WristFloorAnchor. XS still receives the original accepted-wrist 2D input; rawCoco17 retains the original RTMPose values in this path. No 3D wrist coordinates are corrected.

**Automatic live camera/contact anchoring is not implemented.** There is no validated camera-motion/contact/visibility/person-ID detector here. A controlled video harness additionally requires `BPT_SUPPORT_FIXED_REPLAY=1` and an explicitly supplied finite `BPT_SUPPORT_CONTACT_PTS=start:end` source interval. These are assertions by the harness operator, not inferred facts. The interval must not be selected using GT/future contact or occlusion labels and then counted as prediction gain; no GT wrist coordinates can seed the anchor. Outside that interval support clears. The existing readiness/rep latch is only experiment eligibility history, never current floor contact. A lock-protected readiness/reset generation snapshot crosses the MainActor/capture queue; it does not claim current contact. Live/unknown camera has no inferred holds.

The concrete keypoint adapter supplies independent vetoes: finite image-bounded wrist and same-hand rejection, reliable neighboring shoulder/elbow plus very broad nondegenerate forearm/body ratio, and consecutive raw wrist displacement correspondence. Large isolated raw jumps fail correspondence; a coherent relocated observation can pass on a subsequent frame immediately. Body scale averages reliable shoulder-to-hip lengths and never uses wrist length. High score alone cannot satisfy all vetoes. These remain **reliability proxies**, not visibility or identity truth. SimCCDecoder uses min(raw axis argmax scores), not normalized probabilities. Existing push-up logs contain 11,479 scores >1 among 225,777 keypoint scores, range .013–1.201. The core now accepts finite raw scores above 1 without clipping; .7 is an uncalibrated explicit engineering threshold, not 70% certainty.

Native reset boundaries include exact inverse-affine crop-region changes, dimensions, orientation, tracker person recheck switch, reset generation, source time discontinuity and large torso/scale discontinuity. Exact crop resetting is deliberately conservative and may prevent acquiring support during continuous crop updates. The proxy cannot prove person identity; unknown identity/camera conditions must not be represented as detected stable support.

Display override runs **after** the unchanged One-Euro smoother so observed wrists pass without its lag and hidden wrists cannot reappear from filter memory. Inferred forearms use dashed gray strokes with no inferred wrist joint dot; nil hides adjacent segments. OverlaySmoother moved into a pure source file without algorithm changes so focused tests/replay use the actual existing smoothing implementation.

Each immutable output stays in CameraProcessingResult through XS lookahead. Both ordinary evaluator input and ExperimentalCoaching receive assessment copies with uncertain arm elbow/wrist indices invalid, zero confidence and NaN assessment coordinates. Original raw3D remains unchanged. A raw `.ok` becomes `.partial3D` for assessment when a guard arm veto exists, preventing full-observation praise; raw telemetry retains the original model state. ExperimentalCoaching logs `raw_model_state` separately. Pose3D bridge retains its raw model `state` and adds `assessment_state`/`support_invalid` plus a change-detection suffix. No Flutter UI or speech strings changed. When overlay source wrists differ materially from the evaluator's original RTMPose wrist, assessment2D invalidates the wrist instead of certifying different coordinates or replacing raw anatomy.

Focused tests exercise real FormWarningTracker and ExperimentalCoaching paths: raw-ok plus inferred arms cannot produce praise or arm candidates. Native Camera/SwiftUI files receive syntax parsing and project-file lint only; no Xcode/app build, device test, model load or deployment was performed. Swift package tests compile the adapter, original smoother and assessment functions; they do not establish iOS runtime correctness.
