## B. 비교의 의미

- A2D: 기존 RTMPose-m COCO17 앱 재생 CSV의 2D 각도. A: 같은 입력의 MotionAGFormer-XS 원래 H36M checkpoint, 27프레임/lookahead5. 현재 제품의 다른 모델을 뜻하지 않는다.
- B: GVHMR 정적 카메라, 기본 초점거리. GT 체형·키·관절을 예측 입력에 넣지 않는다.
- C: B와 같은 영상 전처리, **데이터셋 정답 카메라 내부 파라미터**의 초점거리. oracle intrinsics 실험으로 분리한다. 실사용자가 이 정보를 제공한다고 가정하지 않는다.
- floor: GT SMPL-X를 같은 H36M regressor로 바꾼 정의 차이 진단. GT가 입력인 oracle이며 추정 모델 성능으로 합치지 않는다.
- Bw/Cw: 중력 정렬 world 몸통 각도 참고. 원래 B/C camera 좌표 기반 판정과 별도 열이다.
- 데드리프트에는 A/A2D가 없으므로 기준 1의 비교에서 제외하고 B/C 결과만 따로 보고한다.

A는 실시간 XS lookahead5 조건이고 B/C는 세트가 끝난 뒤 전체 시퀀스를 받는 GVHMR이다. 미래 정보·지연 조건이 같지 않다. 이번은 post-set 대안 평가이며, 동일 미래 조건을 맞춘 MotionContact A–H ablation이나 실시간 경로 대체의 인과적 성능 비교로 해석하지 않는다. frozen 평가 runner에는 이후 추가한 서비스 관절 지지도·추적 마스크 보류 계약이 없으므로 이 결과가 현재 보류 정책의 정확도를 검증하는 것도 아니다.

판정 일치율은 10/20 고정 evaluator의 legacy 임계값이다. 최신 팀 코칭 CSV의 정확도를 검증한 값이 아니다. 반복 지표는 GT/예측의 **총 개수 차이**로 누락·추가를 추산하므로 서로 상쇄되는 오검출을 잡지 못한다. 시간 대응한 반복 검출 정확도로 확대하면 안 된다.

## C. 기존 결과 재사용 감사

Home `~/gvhmr/fit3d`에서 10/20 결과를 발견했다. 기존 11영상 B/C 22배열, A15개, floor20개를 새 실행 폴더에 복사했으며 원본은 수정하지 않았다. 기존 `score_partial.json`은 8영상 집계여서 전체 결과로 사용하지 않는다.

원래 jobs20개와 새 생성 jobs는 JSON 완전히 동일했다. 당시 개별 job의 wrapper 소스 해시와 일부 회전 메타는 없으므로 clean 원본 작업트리·출력 메타·재채점 재현으로 정합을 확인했으며 과거 job별 실행 바이트까지 입증하는 것은 아니다. `eval_gvhmr_fit3d.py`, `eval_3d_angles.py`, 카운터의 SHA256도 원 소스와 일치했다. 모든 기존 B/C 배열에서 유한값, frame 수, FPS30/원본50, camera focal, upstream ee960bb, half 옵션, calibration β 미사용을 확인했다. 15개 replay의 원영상과 같은 행수·연속 frame ID·시간 단조 증가, A 배열의 길이·유한값도 확인했다. 원본 50fps→30fps pick은 고정 `round(arange(...))`다. 결과 배열은 개별 frame ID를 저장하지 않아 순서 자체를 독립 증명하는 로그는 없고, 고정 코드·프레임 수·원본 replay ID로 정합을 확인했다.

**10/20 당시 원영상 SHA를 저장하지 않았으므로 과거 영상 bytes와 현재 bytes가 같다는 독립 증명은 없다.** 이 한계를 명시하고 기존 11쌍을 조건부 재사용 결과로 분류했다. 현재 입력·camera·rep annotation·GT·replay와 결과·코드의 SHA는 Home `cache_audit_private.json`에 고정했다. 불일치가 나오면 해당 항목은 재사용하지 않는 원칙이다. 이번 전수 검사는 통과했다. 기존 부분 집계8개를 동일 채점 소스로 다시 계산했다. 21개 부동소수점 말단 차이의 최대는 1.42e-14였고 문자열·키·개수 차이는 없었다(수치 재현 일치). 또한 기존22개 결과의 처음·중간·마지막3프레임에서 저장된 **예측 SMPL-X** 파라미터로 camera/world 관절을 CPU 재생성했다(44좌표검사, GT 입력 없음). 현재 SMPL-X→SMPL→H36M 변환과 저장 관절의 최대 차이는 9.54e-7m로 사전 허용1e-4m 안이었다. 따라서 모델/레그레서 변환이 과거 결과와 일치함도 표본 프레임에서 확인했다.

## F. 사전 기준 해석

기준1은 운동별 네 각도 오차의 평균과 판정 일치율을 함께 평가한다. 경계 ±5°에 GT 사례가 있으면 경계 사례를, 없으면 전체 반복을 사용한다. 모든 운동에서 오차가 작고 일치율이 낮지 않아야 해당 B 또는 C가 통과한다. 집계 함수는 경계 사례 회귀가 전체 일치율 향상으로 가려지지 않는지, 한 운동의 평균 오차 악화를 누락하지 않는지 합성 테스트한다.

이 Fit3D 실행은 정사각형 사선 영상이다. 세로 영상 기하 기준, **L4** 60초≤180초와 L4 절대 VRAM≤22GB를 Home pilot만으로 통과시킬 수 없다. 반복 개수 proxy의 한계도 전체 단계 판정에 남긴다.

각도 평균은 세 운동 모두 개선했지만 로우·푸시업의 경계 판정이 낮아 **B와 C 모두 기준1 실패**다. 경계 표본 3개/1개는 매우 작다. 이 일치율은 GT 관절각에서 파생한 임계값 진단이며 실제 사람의 오자세 라벨, 정밀도(precision), 미탐률(FN) 검증이 아니다. 이를 일반적인 성능 열화의 강한 통계적 증거로 주장하지 않지만, 결과를 본 뒤 원래 통과 기준을 바꾸지도 않는다. 몸통 B/C는 frozen scorer의 camera image-up 기준이며 GT는 world-up이므로 좌표 정의 차이를 포함한다. Bw/Cw는 world-up 민감도 참고 열이며 이 열로 사전 B/C 통과 여부를 바꾸지 않았다.

사전 전체 기준의 결론:

1. 각도+판정 일치: **실패**(위 표).
2. 세로 영상 기하: 정사각 Fit3D로는 **미검증**. 인증 20초 세로 스모크는 기능 경로 증거이며 뼈 길이·깊이 폭·직립 기울기 허용범위 검증을 대신하지 않는다.
3. L4 60초 ≤180초: **실패**. 별도 인증 런에서 동일 프로세스 재사용 60초 runner319.048초/worker356.878초. CPU4 단회 진단도 개선을 입증하지 못했다.
4. L4 ≤22GB: **20ms 표본 측정 범위에서 충족**. 기본60초 sampled device-used peak3934.8MiB. 순간 최대를 전부 포착했다는 의미는 아니다.
5. 반복 정확도: 비교 가능한 세 운동의 **순개수 proxy는 비열화**. 사건 단위 시간 대응 정확도는 미검증. 데드리프트는 A가 없어 통과 비교에서 제외한다.

따라서 단계1 전체 통과 및 단계2 채택 조건은 충족하지 않았다. 서버의 실제 인증 업로드·완료·다운로드 성공과 운동 정확도 채택은 구분한다. 별도 L4 증거/버전/제약은 [인증 및 성능 보고서](../results/deep_authenticated_flow_20261026.md)를 따른다. 과거 단일 사용자 체형 비교는 개인화 정확도 개선의 증거가 아니며, 이번 B/C에는 개인 calibration β를 넣지 않았다. 척추 proxy 관측 가능성은 [별도 분석](spine_proxy_20261026.md)에 기록했다.

검증: 집계 기준 합성 회귀 2개와 spine 기하 회귀 2개 통과. 평가 코드·모델을 바꾸지 않고 기존 평가를 완주했으며, 모든 추가 정합 검사는 CPU에서 수행했다.
