# 심층분석 정확도 실패의 시간·극값·기준 반복 분해 — 2026-10-29

**실패 원인이 단순 시간 지연이나 GT 한 프레임 잡음 하나로 설명되지 않음을 실제 보존 배열에서 확인했다.** 로우는 반복 경계 극값에 민감하면서 지속 구간에서도 B/C의 움직임 범위 압축이 남았다. 푸시업은 현재 반복 오차뿐 아니라 모델별로 다른 과거 반복을 최대 폄 기준으로 선택한 것이 FP를 만들었다. 이는 진단이며 원 평가를 PASS로 바꾸지 않는다. 전문가 오자세 라벨이 없으므로 FN/FP는 GT 관절각 문턱 대비 용어다.

사용자 지시 **“속도 신경쓰지말고해”**에 따라 10월29일부터 속도 중심 crop/GPU A/B 작업은 중단했다. 완료된 CPU 자료와 default-OFF 구현은 보존한다. 과거 180초 및 서비스 측정 결과는 기록으로 유지하며 향후 정확도 판단의 새 속도 게이트로 사용하지 않는다. 모델 기본값·학습·배포·원 점수·임계값은 바꾸지 않았다.

## 재현과 자료 경계

계산 전에 [진단 계획](quality_attribution_plan_20261029.md)을 기록하고 Home에 복사했다. [`diagnose_gvhmr_extrema.py`](../../scripts/deep_analysis/diagnose_gvhmr_extrema.py)는 기존 Fit3D 숫자 GT, 동일 50→30fps frame pick, 동일 inclusive 반복 구간, A(MotionAGFormer-XS)/B/C/world/floor 저장 예측을 읽었다. **20개 영상의 저장 반복 점수 4,632개가 전부 정확히 재현됐다(max delta 0)**. 별도 GPU 추론·검출·학습·정규화·미디어 열람은 없다. GT는 평가에만 사용했다. 원 배열·개인 프로필·식별자·입력 경로는 Home에 남았으며 반출물은 [집계 JSON](quality_extrema_20261029.json), 코드와 비식별 해시다. 고정 score SHA256은 기존 `fd84c497…`와 동일하다. evaluator/angle source/helper 및 전체 숫자 입력 cohort hash도 집계에 있다.

B/C 실패 합집합을 먼저 고정했다. 로우는 GT가39.9°±5° 안인3반복 중 **B/C 각각2FN**, 푸시업은 GT relative deficit가10°±5° 안인1반복 중 **B/C 각각1FP**다. 같은 사례에서 다른 모델을 비교했으며 모델별로 유리한 반복을 고르지 않았다. 표본은 로우2개·푸시업1개로 작으며 독립 새 검증 세트가 아니다.

## 로우: 경계 극값에 민감하지만 지속 범위 압축도 있다

| 같은 실패 2반복의 범위 | GT | A/XS | B | C | floor |
|---|---:|---:|---:|---:|---:|
| 원 max−min ° | 42.10–42.77 | 27.25–41.76 | 28.59–34.85 | 28.65–35.19 | 37.70–41.27 |
| P95−P05 ° | 36.70–36.97 | 23.02–37.42 | 24.35–31.19 | 24.37–31.49 | 32.28–36.90 |
| 최대값 한 프레임 제외 ° | 40.42–40.80 | 25.56–40.85 | 27.05–34.01 | 27.09–34.34 | 35.65–40.20 |

GT 최대값은 두 사례 모두 반복의 시작 또는 끝 프레임에 있다. 최대값±2° 연속 지지는1–2프레임(33–67ms), 최소값 지지는8–21프레임(267–700ms)이다. 최대값과 이웃±3프레임 중앙값 차이는2.77–5.05°다. 극값이 짧고 경계에 민감하다는 증거지만 **최대 프레임 하나를 제거해도 두 GT range 모두39.9°보다 크다**. 3프레임 중앙값 필터 진단도 GT range41.93–42.75°여서 단독 이상치 제거가 충분하다는 근거가 없다. 이미지·전문가 검토 없이 실제 동작인지 mocap 오차인지 판정하지 않는다.

중앙값 필터는 반복의 양 끝 값을 복제해 패딩한다. 따라서 endpoint 최고점이 필터 후 남는다는 사실만으로 이상치가 아니라고 판단할 수 없다. 위의 단일 최고점 제거, 이웃값, 지속 범위 진단과 구분해 읽어야 한다.

계획한 P95−P05에서는 GT도36.70–36.97°가 된다. 경계에서3프레임씩 제외하면36.28–38.58°다. 따라서 raw max−min과 sustained range는 다른 표적이다. **동일39.9°를 새 표적에 그대로 적용하거나 이 진단으로 원 FN을 삭제하면 안 된다.** 전체20영상에서 인접 inclusive 반복 구간은83개 endpoint를 공유한다. 이 중복은 frozen 코드 계약과 일치하며 이번에 발견한 배열 정렬 버그가 아니다. 끝 endpoint만 제외한 GT range는40.80–42.77°로 여전히 문턱보다 높다. 시작 endpoint 최대는 이 처리로 제거되지 않는다는 한계도 있다.

동시에 B/C의 P95−P05 오차는 각각 **−12.35…−5.77° / −12.34…−5.47°**다. 즉 짧은 GT 최고점만으로 전체 차이를 설명할 수 없다. GT 최고·최저 시각 그대로 B/C를 읽은 signed range도 각각28.59–34.36° /28.65–34.71°로 작다. B/C 최대 프레임은 GT와 같고 최소 시각 차이는0–167ms다. ±15프레임 탐색의 최적 lag는±1프레임이며, 평균을 제거한 normalized RMS는 B .166–.411→.142–.394, C .158–.409→.134–.391에 그쳤다. **단순 전체 위상 이동보다 진폭/기하 오차가 남는 패턴**이다. lag 탐색은 평가 보정으로 쓰지 않았다.

floor(공식 GT SMPL-X를 동일 H36M regressor로 변환)의 rawrange 오차도−5.06…−.83°, sustained 오차−4.42…−.07°다. 관절 정의/몸통 축 차이가 일부 관여할 수 있지만 floor는 모델 추정의 오차 하한이 아니며 인과 성분을 가산 분해할 수 없다. GT의 near-side shoulder−hip range41.34–43.17°와 thorax−pelvis range32.24–37.47°는 축 정의에 따라 표적이 크게 달라짐을 보인다. GVHMR의 같은 축도 각각28.50–35.26°와25.10–29.73°다. 이 몸통 수직각을 실제 요추 굽힘의 정답이라고 부르지 않는다.

GT를 frozen up 대신 카메라 수직에 맞춘 민감도에서 range 변화는−.275…−.046°였다(두 up 방향 사이11.39–11.76°). 저장 B/C world 출력에서도 rawrange27.02–33.36°로 압축이 남는다. 앞선 네 경계 판정의 camera/world 변경0건과 함께 보면, **up축 하나를 바꾸는 해결책은 지지되지 않는다.**

## 푸시업: “어느 반복이 기준인가”가 FP를 증폭했다

| 같은 실패 1반복 | GT | A/XS | B | C | floor |
|---|---:|---:|---:|---:|---:|
| 현재 반복 elbow_max ° | 155.25 | 161.68 | 140.99 | 141.42 | 137.67 |
| 모델 자신의 running 최대 대비 deficit ° | 7.262 | 3.510 | 11.246 | 10.605 | 7.652 |
| GT와 동일 기준 반복을 사용한 진단 deficit ° | 7.262 | 2.275 | 5.252 | 5.129 | 5.460 |
| 각 반복 P95로 만든 진단 deficit ° | 6.273 | 3.835 | 8.679 | 7.848 | 7.047 |

GT의 running 최대는 현재보다1반복 이전, B/C 및 floor/A의 running 최대는3반복 이전이다. B/C에서 이 **기준 선택 차이**가 자기 running deficit를 동일GT기준 진단보다 각각5.994°/5.476° 높인다. GT 기준 반복에서 B/C elbow_max 오차는−16.271°/−15.963°이고 현재 반복 오차는−14.261°/−13.830°다. 즉 같은 기준 반복으로 비교하면 상대 폄 차이의 오차 방향도 달라진다. 원 계산은 각 모델의 running 최대를 쓰므로 원 FP는 유지한다. GT 기준을 제품 입력으로 넣거나 고르는 해결책은 허용하지 않는다.

원 deficit 오차의 항등식은 그대로다: B running최대 오차−10.277° minus 현재−14.261° =+3.984°; C−10.487° minus−13.830° =+3.343°. 이제 그 running 최대 오차 안에 **GT와 다른 반복을 선택한 효과**가 있음을 확인했다. 현재 반복 최대 시각 차이는B/C 모두33ms, 최저 시각 차이는67ms다. 현재 파형 최적 lag는0프레임이므로 전체 frame pick 지연은 주 원인으로 보이지 않는다.

GT 기준 반복 자체에서 B/C가 고른 최대 시각은 GT 최대와1.867초 떨어져 있지만, 파형 최적 lag는2프레임이고 RMS 개선은B .313→.256, C .307→.248이다. 이는 반복의 양 끝에 있는 폄 구간 중 **어느 최고점을 택하느냐**와 전체 파형 이동을 구분해야 한다는 증거다. 현재 B/C 최대±2° 지지는200ms이며 GT는67ms다. running 기준 최대 지지는B/C67ms, GT100ms다. P95 진단에서 FP 쪽 margin이 사라지는 것은 peak/reference 표적 민감도이며 P95 채택이나 통과 증거가 아니다.

반대쪽 팔꿈치의 running deficit는GT8.12°, B35.09°/C33.68°다. 현재 selected−other elbow_max 차이는GT−3.99°, B+17.28°/C+16.16°다. 양측 기하/관절 복원 차이가 크고 **가까운 쪽 선택을 반대로 바꾸는 것만으로 해결되지 않는다**. floor 현재 elbow_max도GT보다17.58° 낮지만 상대 deficit7.65°는GT7.26°와 가까워, 절대 관절 정의 차이와 상대 판정 안정성을 구별해야 한다.

## confidence와 자기 기준의 한계

세 실패 사례의 GT/A/B/C/floor 좌표는 모두 finite이고 elbow 퇴화 segment(norm≤1e-6)0개다. A 관련2D confidence 평균은로우 .680–.719, 푸시업 .684; B/C는로우 .846–.856, 푸시업 .924이며 관련 관절confidence<.3 비율은 모두0이다. **높은 2D confidence가 3D/각도/자세 정답을 보증하지 않는다.** 당시 observed tracking mask는 저장되지 않아 추적 가시성 비율을 복원하지 않았고, confidence는 전문가 visibility/occlusion 라벨이 아니다.

각 squat/pushup 영상은5반복이다. frozen shallow 규칙은 첫3반복(각 운동25반복 중15개,60%)을 NaN으로 제외하고 첫3개 중앙값을 기준으로 삼는다. GT 첫3개 knee_min 중앙값도영상 간64.63–87.38°, elbow_min은60.60–106.81°로 넓다. 이 차이를 정상/이상 차이라고 단정할 전문가 라벨은 없다. GT의 이후2개 중앙값−첫3개 중앙값은 squat−8.19…+3.04°, pushup−2.44…+3.10°다. B/C의 같은 pushup 변화는−9.62…+2.23°/−8.62…+.15°여서 추정기에서도 기준 대비 변동이 다르다.

running 최대 기준은 새로운 최고점이면 deficit가 반드시0이다. 이 비양수 사례는GT squat11/25·pushup12/25, B/C squat15/25·pushup8/25다. 기준 최대가 첫3반복 안에 머무는 비율의 영상 평균은GT squat92%·pushup80%, B/C 각88%다. 이는 **일관성·기준 대비 악화**를 평가하는 구조다. 처음부터 모든 반복이 충분히 펴지지 않거나 얕아도 “올바른 자세” 표준을 생성하지 못하며, 원 GT 기반 자기상대 평가도 그 문제를 해결하지 않는다. 첫 나쁜3회로 정상 표준을 정하면 안 된다.

## 변경과 다음 정확도 작업

이번 자료에서는 frame pick·반복 점수 재현 버그가 확인되지 않아 production 보정이나 필터를 적용하지 않았다. 반복 경계 공유는 endpoint 정책의 설계 문제이며 원 결과를 소급 변경하지 않는다. 수치 유틸리티의 spike/plateau support, 진폭과lag 구분, endpoint/NaN 계약 **3개 테스트**, 전체 기존 포함 **16개 테스트** 통과; Python compile/git diff check 통과.

검토 브랜치 `ai/final-validation-20261026`에는 정확도 분석 파일만 이식했다. shared-crop 구현을 제외한 해당 브랜치의 CPU 테스트 **8개**가 통과했고 helper 컴파일, 집계 JSON의 helper SHA 일치,20영상/4,632값/delta0 계약, `git diff --check`를 확인했다. Home 계산을 다시 실행하거나 GPU·기기를 사용하지 않았다.

다음 정확도 실험은 세 실패에 맞춘 threshold 튜닝이 아니라, **관절 축·반복의 폄/굽힘 phase·절대 정상 표준의 정의를 먼저 고정하는 것**이다. 전문가 또는 운동별 독립 기준으로 정상/경고/판정불가를 정의하고, raw extreme와 sustained phase 측정·기준 반복의 불확실성을 별도 독립 사례에서 비교해야 한다. unilateral 관절 복원과 row 진폭 보존을 각각 정량 목표로 삼되, GT 입력/모델별 유리한 side 선택/자기 첫3회 정상화는 하지 않는다. 새로운 기준·전문가 라벨·독립 검증 없이 현재20개를 재사용해 제품 정확도 통과나 안정성을 주장하지 않는다.

후속 비교를 시작하기 전에 필요한 증거는 다음과 같다.

- 반복별 전문가 정상/구체적 오류/판정불가 라벨과 근거, 관절 중심·몸통 축·좌우 side 정의, 독립적인 폄/굽힘 phase 구간. 이 라벨을 첫3반복의 모델 출력으로 만들지 않는다.
- 원20개와 중복되지 않는 검증 분리 및 라벨/규칙 고정 시점. 경계 사례뿐 아니라 문턱에서 먼 사례, 정상 폄을 끝내 못 하는 세트, 첫3회부터 같은 오류인 세트, 양측 가림 사례의 분모를 공개한다. 현20개에서 새 기준을 정했다면 그20개는 개발/진단 자료로만 취급한다.
- 같은 영상/frame pick·모델 출력·side를 고정한 raw extreme, sustained phase, 자기상대 악화, 독립 절대 기준의 병렬 비교. 반복별 FP/FN/판정불가 및 신뢰구간·phase 정렬·지속시간을 함께 보고, 평균 각도 MAE만으로 채택하지 않는다.
- GT 강제 동일 reference는 **오프라인 진단 전용이며 앱·서버 추정 입력에 적용 금지**다. 제품은 독립 정상 표준이 확인되지 않으면 “정상”으로 확정하는 대신 근거 범위를 표시하는 정책부터 검토한다. 이 보고서는 새 UI/제품 정책을 배포하지 않았다.

이 증거 없이 유일한 FP를 없애는 P95/스무딩, row39.9° 변경, 기준 반복을 유리하게 고르는 조정은 하지 않는다.
