### 지표 설명
- 렙 정확도 = (정답 렙 − 놓친 렙) ÷ (정답 렙 + 더 센 렙). 정답 렙의 가장 깊은 프레임(gt.json)과 앱이 센 렙의 끝 프레임을 순서대로 맞춤(outputs/rep_validation/analyze.py와 같은 방식).
- 정지 구간 지터: Exercise3D 3D 라벨에서 앞뒤 2프레임 동안 모든 관절 이동이 0.0025 미만인 프레임만 골라,
  2D 키포인트의 프레임 간 가속도 |p(t+1) − 2p(t) + p(t−1)|(원본 해상도 px, 신뢰도 0.3 이상 관절) 평균. 영상별 평균의 중앙값.
  (중앙값으로 재면 전체 프레임 입력의 좌표 해상도(가로 2.81px, 세로 3.75px 계단) 때문에 값이 계단에 붙어서 평균을 씀.)
- 튜닝/검증(held-out): 피험자 단위. P1 = 튜닝, P2·P3 = 검증 (사람 구분은 영상 육안, 추정). 푸시업은 P1뿐이라 검증 없음.

## 트랙 D — 3D (ai/pose3d)

한 줄: 3D(MotionAGFormer-XS)는 사선에서 일부 각도를 덜 틀리지만 측면 2D 수준에 못 미치고 렙 카운트도 낫지 않으며, iPhone에서 프레임당 +17 ms가 들어 라이브 3D는 계속 끔. 측면 요구도 유지. 결정 D-D-01–06.

### 만든 것 (앱 동작 변경 없음)
- `scripts/eval_3d_angles.py`: 앱 2D(pose-replay CSV) vs 3D(앱과 같은 person_crop·27프레임·lookahead 5) 각도를 Fit3D 모션캡처 / Exercise3D 라벨과 비교. 가까운 쪽 = 앱 규칙(신뢰도). 무릎 경첩 감지 데이터도 남김. `--ex3d-replay`로 crop 입력 재생 결과 사용, 영상 크기는 재생 JSON에서 읽어 영상 없이 Home에서 실행 가능.
- `scripts/summarize_3d_angles.py`: 시점 구간 × 묶음(Ex3D P1 튜닝 / P2·P3 검증, Fit3D 피험자)별 중앙/p90, 무릎 경첩 감지 표.
- `scripts/count_reps_3d_vs_2d.py`: 같은 카운터로 2D·3D 각도 신호 렙 수 비교 + 앱 상태기계 수.
- `scripts/finetune_motionagformer_fit3d.py`: 앱 2D 입력 + Fit3D 3D 정답으로 XS 미세조정, 피험자 분할, MPJPE(mm).
- `tools/ios_live3d_cost`: 사람 없이 iPhone에서 RTMPose-s 단독 vs +MotionAGFormer-XS 30 fps 지연·CPU·발열(XcodeGen 앱, `run.sh`).

### 결과 요약
- 사선 각도(D-D-01): Fit3D 60–75° 렙 극값 스쿼트 무릎 2D 21–36° → 3D 7–11°, 로우 팔꿈치 61–79° → 8–25°지만, 측면 Ex3D 스쿼트 몸통은 3D가 더 나쁨(1.5–2.9° → 9–11°). 남는 오차가 경고 기준보다 커서 측면 요구 유지.
- 렙 카운트(D-D-04): 같은 카운터에서 2D 신호가 3D 신호보다 같거나 정확(Fit3D 스쿼트 8/8 vs 4/8). 앱의 Fit3D 사선 스쿼트(s03·s05, crop) 41/40.
- 3D 불량 감지(D-D-03): 큰 3D 오차를 스쿼트·로우에서 0% 잡음, 푸시업에서만 15–35% 프레임에 걸림.
- iPhone 17 비용(D-D-05): 30 fps에서 2D 9.4 ms → 2D+3D 26.2 ms, CPU 23 → 36%, 3분씩 발열 단계 변화 없음.
- Fit3D 미세조정(D-D-06, Home GPU): 학습 안 한 피험자 MPJPE 160 → 50 mm(s05→s03), 163 → 67 mm(s03→s05). 독립 Exercise3D에서 사선 스쿼트 무릎 렙 극값 오차 16.7 → 1.3°(40–60°)로 크게 좋아졌지만 카메라 기준 몸통은 나빠짐(2.9 → 27°). 앱에는 아직 안 넣음, 다음 단계 1순위.

### 테스트
