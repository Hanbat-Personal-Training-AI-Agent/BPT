## 트랙 pushup-fix — 측면 푸시업 렙 카운트 일반화 (ai/pushup-fix)
- MM-Fit 사람 단위 분할을 먼저 결정 문서에 고정(D-T3-09, 조정 9명 / 검증 6명), Fit3D 가상 측면 s03–s05 / s07–s11, Exercise3D P1 조정.
- 버그 후보 1(crop 고정) 확인 → crop 경계 재맞춤(D-T3-10). 후보 2·3·4는 모두 "팔꿈치 각도 하나로 셈"이 원인이라 어깨 높이 신호 하나로 처리(D-T3-11, Python 원형으로 조정 데이터에서 범위 창·게이트·결합 방식 선택 후 Swift 구현).
- 검증: MM-Fit 80.4 → 94.5%, Fit3D 가상 측면 61.4 → 80.1%. 회귀 표 전부 같음, iPhone 17 키포인트 39/39 일치.
- 코디네이터 요청으로 MediaPipe Pose full(푸시업만) 후보 비교(Home CPU에서 키포인트): 조정에서 RTMPose 경로가 앞서 채택 안 함(D-T3-12). iPhone MediaPipe 검증은 후보가 조정 비교에서 탈락해 하지 않음.
- 새 공개 데이터(data-collect의 Mendeley·YouTube CC)는 렙 정답 파일이 아직 없어 이번 검증에 못 씀.
- 진행 중 문제: 공유 디스크가 다른 트랙 때문에 3–6 GB로 떨어져 Core ML 작업을 자동 일시정지(6 GiB 기준), heavy 잠금이 반복 작업에 불공정(5초 폴링) — 내 작업은 같은 잠금에 0.2초 폴링으로 줄 섬. Fit3D 사선 s08–s11은 시간 때문에 m만.
- 정리: MM-Fit 클립·키포인트, Fit3D 실제 영상(한 개씩 받아 바로 삭제)·합성 CSV, iPhone용 클립, Home ~/pushup-fix 삭제.
- 병합: integration/ai 2b366b1(fast-forward), swift 96, pytest 185, server 82+1 skip, flutter 79, xcodebuild sim OK.

- 병합: integration/ai 2213aa8(fast-forward, b68ce19 위). 회귀: swift 96, pytest 189(+4 `tests/test_data_collect.py`), server 82 + 1 건너뜀, flutter 79, xcodebuild 시뮬레이터 성공. xcodebuild는 처음에 "sandbox is not in sync with the Podfile.lock"로 실패 → integration 워크트리에서 `pod install`(CocoaPods 1.16.2)로 Pods를 다시 맞춘 뒤 성공. 그때 생긴 `ios/Podfile.lock` 로컬 변경(Flutter 체크섬·COCOAPODS 줄)은 커밋하지 않음(팀 파일, 환경 문제).
