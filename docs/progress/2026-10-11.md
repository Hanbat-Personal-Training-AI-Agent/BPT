## 실기기 전체 파이프라인 (ai/device-pipeline)
- `tools/pose_model_bench` 호스트 앱에 영상 입력 라이브 모드(`Host/PipelineBench.swift`, `run_pipeline.sh`): AVAssetReader 디코딩 → 라이브 카메라와 같은 프레임 코드. 30 fps 페이스 / 무제한, 녹화·3D·m 변형, 10초마다 FPS·놓친 프레임·발열·배터리, 기기 키포인트 CSV 내보내기(`BENCH_DUMP=1`).
- 프레임당 포즈 단계를 `RTMPoseCropTracker.estimate`로 뽑아 CameraPosePreview·pose-replay·벤치 공통(동작 그대로, 새 테스트 1개).
- 실수 정정: 처음 푸시업 영상(가로 1920×1080)을 세로 720×1280으로 늘려 렙이 2–4로 나옴 → 가로 1280×720으로 다시 만들어 전부 재측정(먼저 잰 a 결과는 버림).

## 트랙 three-ex — 스쿼트·푸시업·바벨로우 시점별 렙 카운트 (ai/three-ex)
- 평가 틀: 영상마다 Core ML RTMPose(crop 입력)로 키포인트를 한 번 뽑아 캐시(Exercise3D 39영상 × s·m·Halpe26, Fit3D 8명 × 스쿼트·푸시업·로우(+조정 피험자는 다이아몬드·데드로우) × 카메라 4대 × s·m, iPhone s 28영상), 규칙은 `pose-replay --keypoints-csv`로 재생. 수정 전 = integration `675d3e5` 빌드. Fit3D 분할은 결과 보기 전 고정(s03·s04·s05 조정, s07–s11 검증).
- Fit3D: Home으로 옮겨진 아카이브에서 정답(rep_ann·3D 주기성 46/46 일치)·시점 각도를 Home에서 계산, 영상은 피험자 하나씩 Mac으로 받아 키포인트만 뽑고 바로 삭제(Mac에 남은 Fit3D 원본 없음, 키포인트 CSV는 scratchpad, 집계만 문서에).
- pose-replay 손잡이 추가: `--side-cutoff`, `--row-offside off`, `--pushup-ankle on|off`, `--pushup-wrist-conf`, `--pushup-min-frames`, `--model mcoco17`.
- 바뀐 동작: 로우 비측면 렙 카운트(D-T3-01), 푸시업 발목 해제·최소 15프레임(D-T3-02), 로우 빠른 내리기(D-T3-03), 운동 카메라 m COCO17(D-T3-05). 스쿼트는 그대로(D-T3-04, 기준선 재설정 시도는 기각).
- 진단에서 확인한 것: Fit3D 사선 로우가 0–30%였던 이유는 전부 게이트(렙 판정 안 함), 규칙 자체는 93–95%. 후면 로우는 2D 팔꿈치가 펴진 채라 휴식 판정이 안 풀림. 푸시업 사선 놓침은 발목·손목 신뢰도 0.1–0.27, 추가는 엎드리기·일어서기. 스쿼트 사선 추가는 전부 세트 전후 바닥 바 들기·내리기.
- iPhone: `BENCH_DUMP=1`로 39영상 키포인트를 뽑다가 기기가 잠겨(passcodeRequired) s 28영상(로우·푸시업 전부, 스쿼트 1)만 받음, m은 못 돌림. 받은 것에서 측면 렙 수는 수정 전후 모두 정답과 같음.
- 실수 정정: 처음 sway 결과를 `tail`로 잘라 렙이 난 합성 건 목록을 잃어 다시 돌림. 스쿼트 기준선 재설정은 검증 피험자(s11)에서 찾은 수정이라 기각.
- 테스트: swift 87 → 92(로우 비측면 카운트·안내 1회, 로우 빠른 내리기, 푸시업 짧은 렙 버림, 발목 없이 카운트, 운동/캘리브레이션 모델 선택).
- 결정: D-T3-01–07, 결과 `docs/results/summary.md` §9.

## 트랙 pushup-heldout — 측면 푸시업 검증(P1 아닌 사람) (ai/pushup-heldout)
- 측정만. A(Fit3D 가상 측면 합성)·B(공개 실제 영상)를 병렬로.
- A: Home에서 Fit3D 8명 모캡을 가상 측면 0/20/40°(720×1280, 높이 0.5 m, 3.5 m — 3.0 m는 몸이 화면 밖으로 나가 바꿈)로 투영. COCO 정의 오프셋은 조정 피험자 실제 영상(Mac Core ML, 12영상 받아 키포인트만 뽑고 삭제)으로 맞춤. 잡음은 Exercise3D 측면 푸시업 RTMPose-m − Sapiens2 잔차를 영상 통째로 재사용. 합성 CSV는 Mac pose-replay `--keypoints-csv`로 재생 후 삭제.
- 발견: s07·s10은 팔꿈치를 옆으로 벌리는 푸시업이라 측면 2D 팔꿈치 각도가 거의 안 바뀜 → 측면에서 놓침(오차 없는 투영도 같음).
- B: 후보 6+개 조사, MM-Fit(CC BY 4.0, Zenodo)만 조건 만족. 푸시업 세트 65개만 HTTP range로 잘라 받음(약 330 MB) → 측정 후 삭제. 버그 후보 3개(crop 고정, 팔 선택, 첫 렙 덜 펴짐)는 증거만 기록.
- 실수: 첫 키포인트 추출 스크립트가 출력 파일 이름을 `_coco17`로 가정(실제 `_mcoco17`)해 두 영상을 다시 돌림.
- 결정 D-T3-08, 결과 `docs/results/pushup_heldout_side.md`, summary §10.
