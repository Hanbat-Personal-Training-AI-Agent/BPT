# Native fault trace Stage 1 validation

The opt-in source/operand trace covers the 20 existing core-three rules without changing their arithmetic, thresholds, report dictionary, event ordering or delivery defaults. `BPT_NATIVE_FAULT_EVIDENCE=1` enables a new bounded live capture; absent that flag the recorder is nil. The live stream is explicitly observed-judgements-only, and cannot certify an entire source interval. This stage does not create strict imported decisions or backfill the frozen 588 tasks.

Core API commit: `27961170b4ca5dcdadf72a1d422fed7f7e7a0246`. The follow-up adds camera lifecycle binding, recorder-lifetime rep identities, invalid-JSON rejection and regression tests. The library and PoseReplay target both compile the same symlinked source; Xcode registration is included.

Validation command:

```sh
BPT_FAULT_TEST_TRACE=/private/tmp/native-fault-actual-fixture.jsonl \
  swift test --package-path ios/CalibrationEngineKit \
  --filter 'FormFaultEvidenceTests|FormWarningsTests'
```

Final result: **60 tests passed, 0 failures** (44 existing form-warning tests and 16 trace tests). The tests cover exact report/event equality with capture on/off; true/false/nil/not-called; quiet execution versus delivery; partially supported lockout OR and actual short circuit; finite helper/manual thresholds; first-N references; whole-rep bottom selection and sparse first-available references; explicit unknown view; missing/partial selected 3D; all 20 IDs; expected-source identity and flush; ingress/observation failures; cap, write failure, invalid JSON, and exclusive files; and unique rep identities/history clearing across reset and tracker replacement.

The invalid-JSON regression first exposed a Darwin `NSInvalidArgumentException` on NaN, which Swift `catch` does not intercept. The final recorder checks `JSONSerialization.isValidJSONObject` before encoding. Earlier failing attempts are retained alongside the passing log.

Four actual-tracker **synthetic** JSONL fixtures are generated by the tests. The main fixture compares default reports/events byte-for-byte. Additional pushup/squat/barbell-row fixtures use explicit test-only config overrides and known input geometry to exercise rule paths; they are neither production thresholds nor accuracy data. Every record is emitted by the real tracker/judge, not an authored decision JSON. Some fields/rules remain unavailable by construction, and Stage 2 must withhold accordingly.

Durable artifacts: `~/bpt-data/completion-20261104-private/native-fault-evidence/`. `artifacts.json` contains byte counts and SHA-256 for logs and synthetic fixtures; `commands.json` records reproduction; `source_hashes.json` pins the producer and test generator. The final passing log is `native-fault-trace-tests-final5.log`.

No phone, UI, model inference, training, deployment or integration was performed by Stage 1. The camera hook still requires the coordinated combined iOS typecheck, and the separate exporter/headless CLI require their own provenance and source-completeness validation. A recorded false or fired key alone never establishes strict negative or positive coverage; stateful facing may predate capture, majority side does not replace per-frame side, and partial 3D is not complete rule support.

The final source-only review added exact facing-branch observations (`seen`, establish/confirm/candidate/flip and before/after candidate counts) alongside finite joint support. A regression preserves the native +infinity-coordinate branch result while explicitly marking its source nonfinite, so it cannot serve as silently valid provenance. This changes trace metadata only.
