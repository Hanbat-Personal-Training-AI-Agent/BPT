# 2D 모델(COCO17 vs Halpe26)이 MotionAGFormer-XS 3D에 주는 영향 — 모델 평가 (ai/lift-compare, D-T3-22)

2026-10-19 · 브랜치 `ai/lift-compare`(integration/ai c113150 위) · 사전 등록 계획 [lift_compare_plan.md](lift_compare_plan.md)(제안, 미승인; v1 da6d7f6 → v3 06935b9, 모두 본 실행 전) · 제약용 통계 [lift_compare_priors.md](lift_compare_priors.md)

**이 문서는 모델 평가만 한다.** 채택·기각, 앱 변경, 병합, 새 학습은 없다. 앱 적용 가능성(속도·통합)은 §9에 따로 적고, iPhone FPS·종단 지연은 ai/lift-app 담당이라 여기서는 **측정 안 함**.

## 0. 한 줄 답
- **같은 사람 상자(실험 A), Fit3D 모캡 정답, 검증 피험자에서**:
  - **원래 H36M XS**에서는 Halpe26(변형 a, COCO 부분)이 COCO17보다 3D 위치가 **조금 더 정확**하다. MPJPE −1.8 ~ −3.9 mm, P-MPJPE −2.2 ~ −4.4 mm, 95% 피험자 부트스트랩 CI가 0을 넘지 않는다(상자 규칙·정규화 6조합 중 5조합에서 사전 규칙 "차이 있음", 1조합은 MPJPE가 문턱 2 mm 아래). 관절 각도(무릎·엉덩이·팔꿈치·몸통 렙 극값)는 **구별 불가**.
  - **Fit3D 미세조정 XS(D-D-08 d, COCO17 앱 2D로 학습)**에서는 차이가 **없다**고 구별할 수 없을 만큼 작다: MPJPE +0.4 / −0.4 mm, CI가 0을 포함.
  - 변형 b(Halpe 자체 골반·목·머리)는 두 리프터 모두 **나빠진다**(MPJPE +6 ~ +11 mm, 미세조정 XS 무릎 +3.8°).
- 그러므로 3D 정확도에서 **2D 모델 선택의 효과는 리프터 선택(원래 vs 미세조정: MPJPE 113–156 → 52 mm)이나 정규화(원래 XS crop 156 → screen 113 mm)보다 한 자릿수 작다.**

## 2. 무엇을 비교했나
- **2D (실험 A, 같은 상자)**: 프레임마다 RTMDet-m 사람 상자(점수 ≥ 0.2, 점수×넓이 최대) 하나를 RTMPose-m COCO17(`d8dd5ca4`, 앱 `rtmpose_m_forward`의 원본)과 RTMPose-m Halpe26(`4d3e73dd`)에 똑같이 줌(Home PyTorch mmpose 1.3.2). 앱은 Core ML이라 Core ML 변환 오차는 이 비교에 없다.
- **XS 입력 매핑**: `coco` = 앱 매핑(`coco17_to_motionagformer_h36m17` = Swift `coco17ToH36M17`, 같은 식), `ha` = Halpe26 0–16에 같은 매핑(**주 비교, 파이프라인 B**, 지금 앱이 Halpe26에서 하는 것과 같음), `hb` = 골반←Halpe 19 Hip, 흉곽←18 Neck, 머리←17 Head(부차, 실험), `*_mp` = MediaPipe Hand 손목 교체(`run_hand_stage`와 같은 규칙), `gt2d` = 투영 모캡 2D(리프터만의 오차를 보는 참고 상한).
- **정규화**: `crop` = 앱 기본 person_crop(D-12), `screen` = MotionAGFormer H36M 학습 설정(`X/w×2−[1,h/w]`, 전체 프레임). §5.
- **리프터**: `orig` = `motionagformer-xs-h36m.pth.tr`(sha256 7abb32ea…), `ftd` = **D-D-08 변형 d** `~/models/bpt-smpl-train/d.pth`(sha256 04f08ecc…; Fit3D s03–s05로 미세조정한 XS + 뼈 길이 FiLM 조건, 조건 = 피험자별 SMPL-β 맞춤 길이 = D-D-08 oracle 설정). **D-D-06/07의 미세조정 XS는 가중치가 지워져 없다**(D-D-07 정리, Mac·Home·Modal 확인) — `ftd`는 그것과 같은 가중치가 아니다. `ftd`는 crop만(학습 설정).
- **제약**: `raw`, `con_app` = ai/lift-app `Pose3DConstraints`(ed67a6e, 기본 한계·세션 뼈 길이), `con_fit3d` = 같은 클래스에 한계·사전 길이만 Fit3D s03–s05 모캡 값(priors 문서).
- 앱과 같은 27프레임 창·lookahead 5·선택 행. 출력 → mm는 정답 골반 깊이로 약원근 환산(모든 변형 같은 "정답 크기 힌트"; P-MPJPE는 영향 없음).
- 지표 정의: 계획 §4(ai/lift-app과 공유). 렙 = Fit3D `rep_ann` 경계, 각도의 가까운 쪽은 정답 기하로 정함(모델마다 같음). 몸통 `torso_g` = 중력 기준.
- **비교 규칙(사전 등록)**: 쌍 차이(변형 − coco, 같은 영상·프레임)의 피험자 묶음 부트스트랩 95% CI(2,000회)가 0을 넘지 않고 |차이| ≥ 문턱(위치 2 mm, 가속도 0.5 mm/프레임², 각도 1°)이면 "차이 있음", 아니면 "구별 불가"(같다는 증명 아님).
