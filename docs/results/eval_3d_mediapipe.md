# 3D 정확도: MediaPipe Pose 월드 3D vs MotionAGFormer-XS vs 앱 2D (Fit3D 모캡 정답, D-D-07)

2026-10-12, 브랜치 `ai/eval-3d-mp`. 스크립트 `scripts/eval_3d_mediapipe.py`(+ `eval_3d_angles.py` 엉덩이 각·json 관절 읽기, `finetune_motionagformer_fit3d.py` 영상 단위 `prep`). 데이터·중간 결과는 저장소에 없음(Fit3D 라이선스: 사용자 본인 Mac·Home에서만, 집계값만 기록).

## 용어 (쉬운 말)
- **MPJPE**(관절 위치 오차 평균, mm): 예측 3D 뼈대와 정답 뼈대를 **골반 위치만 겹친 뒤**, 관절 17개 각각이 정답에서 몇 mm 떨어졌는지의 평균. 몸이 기울어진 방향(회전)·크기가 틀려도 그대로 오차에 들어간다 → "카메라 기준으로 자세를 얼마나 맞게 놓았나".
- **PA-MPJPE**(정렬 후 오차, mm): 예측 뼈대를 정답에 가장 잘 맞도록 **돌리고·키우고·옮긴 뒤**(Procrustes) 남는 오차. 방향·크기 문제를 빼고 "관절끼리 모양(굽힘 정도)이 맞나"만 본다. 항상 MPJPE ≤ 값.
- **가속도 오차**(mm/프레임², 30 fps): 프레임마다 관절 위치의 2차 차분(가속도)이 정답과 얼마나 다른지 → 떨림. **각도 떨림**: 같은 것을 각도(°/프레임²)로.
- **렙 극값 오차**(D-D와 같음): 렙마다 무릎·엉덩이·팔꿈치 각 최솟값, 몸통 기울기 최댓값을 정답과 비교한 차이(°)의 중앙값. 경고는 이 극값으로 판정하므로 가장 중요한 수치.
- 몸통: `torso` = 엉덩이 중심→어깨 중심이 **카메라 위쪽(-y)**과 이루는 각(지금 앱이 볼 수 있는 것), `torso_g` = **실제 중력 위쪽**과 이루는 각(기기 가속도계가 있다고 가정, 정답 카메라 자세로 계산). 2D는 둘 다 화면 세로축 기준(같은 값).

## 방법
- **영상**: Fit3D 스쿼트·푸시업·바벨로우 × 카메라 4대 × 피험자 8명(조정 s03–s05 36영상, 검증 s07–s11 60영상). 50 fps → 앱의 30 fps로 골라냄(D-D와 같은 프레임). Fit3D 카메라는 모두 사선 56–75°, 약 9–12° 내려다봄 → **측면(≤40°)은 Fit3D로 못 잼**.
- **앱 2D**: Mac `pose-replay --model mcoco17`(RTMPose-m COCO17, crop 입력 = 현재 앱 기본, D-T3-05). D-D-01–06은 RTMPose-s였음 → 2D 수치가 D-D와 조금 다름.
- **MediaPipe**: Pose Landmarker lite/full/heavy(`float16/latest`, D-C-07과 같은 공식 URL·sha256 59929e1d…/4eaa5eb7…/64437af8…), Python 0.10.21, VIDEO 모드, 전체 프레임, 타임스탬프 30 fps, 기본 신뢰도. `pose_world_landmarks`(미터, 엉덩이 중심 원점). 축 확인: x 오른쪽·y 아래·z 카메라에서 멀어짐 = 카메라 좌표와 같음(z를 뒤집으면 s03 MPJPE 114–200 → 264–613 mm로 나빠짐).
- **MotionAGFormer-XS**: 원래 H36M 가중치(`mag_orig`)와 Fit3D 미세조정(`mag_ft`). 앱과 같은 27프레임 창·lookahead 5·person_crop 입력. 미세조정은 D-D-06 다음 단계대로 **조정 피험자 s03·s04·s05 전부**(5운동 × 4캠 = 60영상, 앱 m 2D 입력), 10에폭, 배치 16, Home GTX 1060(에폭 440초). 검증 피험자는 학습·선택에 안 씀(마지막 에폭 그대로). 출력은 crop 단위라 정답 골반 깊이로 mm 환산(약한 원근) — MediaPipe에는 없는 "정답 크기 힌트"가 들어간 값이라 MPJPE는 MotionAGFormer에 유리. PA-MPJPE는 크기를 다시 맞추므로 공정.
- **관절 대응** BlazePose 33 → H36M-17: 골반 = 두 엉덩이(23·24) 중점(MediaPipe 원점과 같음), 오른/왼 엉덩이·무릎·발목 = 24/26/28, 23/25/27, 흉곽 = 두 어깨 중점, 척추 = 골반·흉곽 중점, 9 = 코(0), 머리 = 두 귀 중점(H36M 머리는 정수리라 약 10 cm 위), 어깨·팔꿈치·손목 = 11/13/15, 12/14/16. 각도는 D-D처럼 2D 신뢰도로 고른 가까운 쪽.
- **Exercise3D**: 측면(≤40°)·사선(40–75°) 캠 28영상, 앱 m 2D(three-ex 캐시)와 MediaPipe·MotionAGFormer. 라벨은 Sapiens 삼각측량 = **정답 아님**, 같은 라벨로 소스끼리 상대 비교만. 측면 푸시업은 P1(조정)뿐.

## 정의 차이(오프셋): MediaPipe 엉덩이·어깨 vs Fit3D 모캡
팔다리 관절(무릎·발목·팔꿈치·손목)만으로 예측을 정답에 맞춘 뒤, 남는 차이를 정답 몸 좌표(옆 = 몸 오른쪽, 위 = 몸통 위, 앞)로 본 중앙값(mm, 검증 s07–s11; 조정 s03–s05도 같은 방향·비슷한 크기).

- **엉덩이**: MediaPipe 엉덩이 폭이 모캡 고관절 중심 폭의 0.70–0.76배(안쪽으로 각 2–3 cm), 높이는 7–10 cm 아래. 골반(원점)도 같이 7–9 cm 아래 → 루트 기준 MPJPE에 모든 관절이 이만큼 밀려 들어간다.
- **어깨**: 폭은 1.15–1.20배(어깨 끝 쪽, 모캡은 어깨 관절 중심), 높이는 3–5 cm 아래, 흉곽 7–9 cm 아래. 몸통 길이 비는 1.00 → 몸통 **기울기**에는 영향이 작음(추정).
- 머리 10–12 cm 아래는 정의 차이(귀 vs 정수리)라 예상대로. 이 오프셋은 보정하지 않고 그대로 잼(보정값을 조정 피험자로 맞추면 검증에서 MPJPE는 줄겠지만 각도 결론은 안 바뀜, 추정).

## 한계
- Fit3D는 사선 56–75°뿐(측면·완전 정면 없음), 모두 체육관 한 곳·같은 카메라 높이. 측면 결론은 정답 아닌 Exercise3D뿐.
- 중력 몸통은 정답 카메라 자세로 만든 "완벽한 가속도계" 가정. 실제 기기 가속도계 잡음·흔들림은 안 넣음.
- 미세조정 가중치는 Fit3D 유래(비상업, 캡스톤 용도만). 피험자 3명 학습.
- 틀린 자세 영상이 없어 경고 검출률은 못 잼(브리프 4절) — 각도 오차만으로는 경고 켜기 근거가 안 됨.
- MediaPipe는 Python 0.10.21(CPU), iOS 1.0.0과 수치가 같다고 가정(추정).

## 재현
Home(`bpt-home`, `~/bpt-work`):
```
eval_3d_mediapipe.py mp-fit3d --root ~/datasets/fit3d --models <task 3개> --subjects s03,s04,s05,s07,s08,s09,s10,s11 --out MP
finetune_motionagformer_fit3d.py --root ~/datasets/fit3d --replay REPLAY --train s03,s04,s05 --test s07,s08,s09,s10,s11 --epochs 10 --batch 16 --out FT.pth
eval_3d_mediapipe.py fit3d --root ~/datasets/fit3d --replay REPLAY --mp MP --ft FT.pth --subjects ... --out fit3d.json
eval_3d_mediapipe.py ex3d --outputs EX3D --replay MREPLAY --mp MP_EX3D --ft FT.pth --out ex3d.json
eval_3d_mediapipe.py offsets ... ; eval_3d_mediapipe.py table fit3d.json
```
REPLAY = Mac `pose-replay --exercise squat|pushup|row --model mcoco17 --motion3d none` CSV를 `REPLAY/<피험자>/<캠>/<운동>_*coco17.csv`로. 모든 중간 파일(영상 복사·CSV·MediaPipe 출력·체크포인트)은 측정 후 삭제.
