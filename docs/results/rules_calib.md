### 요약 (쉬운 말)
- **지금 앱 기준값은 정상 동작에도 자주 경고한다**(Halpe26 입력, 원래 XS, held-out 정상 렙 기준). 이것이 사용자에게 가는 가짜 경고다.
  - 스쿼트 덜 일어섬: 52%.
  - 무릎 모임: 공개 영상 63%, Fit3D 90%.
  - 푸시업 팔 덜 폄: 23%.
  - 엉덩이 들림: 11%.
  - 덜 내려감: 11%.
  - 고개 듦: 10%.
  - 뒤꿈치 들림: 50–81%(지금은 꺼져 있어서 실제로 울리지는 않는다).
- **사전 등록 규칙으로 기준값을 다시 정하면 오경보는 대부분 5% 아래로 내려간다.** 그 대신 기준이 아주 느슨해져서 틀린 자세를 거의 잡지 못한다. 예를 들어 스쿼트 덜 앉기 30.8°, 덜 일어섬 90.6°, 원래 XS 무릎 모임 0.22다. 그래서 "근거 있음"을 받은 규칙은 **하나도 없다**. 대부분 "근거 약함"(오경보는 목표 안이지만 검출을 보이지 못함)이고, 일부는 "끄기 권장"이다.
- 사용자가 예로 든 로우 규칙(상체 숙임, 무릎 각, 당기는 모양)은 3D로 **잴 수는 있다**. 하지만 틀린 자세 라벨이 held-out에 0–2개뿐이라 **잡는지는 알 수 없다**. 손목 굽힘은 손 관절이 없어 **잴 수 없다**.
- 공개 영상의 정상 렙에서 칭찬(praise_good)이 나올 수 있는 렙 비율이 크게 늘었다. 스쿼트는 40% → 99%, 푸시업은 63% → 91%다. 로우는 75% → 69%로 줄었는데, 새 로우 키가 정상 렙에서도 울리기 때문이다.

### A. 검증된 사실
1. **데이터와 출처**(사전 등록 그대로, Halpe26 입력은 사용자 결정 20:50). 도출 렙 수:

   - C1: 공개 조정과 Exercise3D P1. C2: 공개 조정만.
   - 평가: Fit3D s07–s11(로우 22렙, 무릎 모임·뒤꿈치 100렙), 공개 held-out 정상(푸시업 264, 스쿼트 123–377, 로우 12), Exercise3D P2·P3(스쿼트 14–30, 로우 40).

3. **검출**(AI 2패스 합의 라벨, held-out bad 클립, 앱 게이트를 통과한 클립만): 라벨 클립이 규칙마다 0–7개뿐이다.

     - pushup_depth_abs: C1 3/3(p = 0.001), C2 2/3(p = 0.022). 라벨 클립이 5개보다 적다.
     - row_torso_swing: C1·C2 6/7(p = 0.045). Fit3D 오경보가 C1 23%, C2 18%다.
   - 원래 XS의 row_torso_swing 검출은 5/7(p = 0.12)이다.
   - 공개 데이터 squat_shallow 라벨 클립 4개, squat_torso_lean 라벨 클립 5개(합의)는 rc1에서 거의 잡히지 않았다(0/4, 1/5).
4. **판정 분포**(원래 XS, 30개 규칙·방향): 근거 있음 0, 근거 약함 23, 끄기 권장 7.
   - 끄기 권장: pushup_hand_position(도출 n < 20), pushup_lockout_abs(공개 6%), row_standing_up(Ex3D 38%), row_short_pull(Fit3D 9%), row_pull_low(Ex3D 25%), row_straight_arm(Ex3D 25%).

5. **지표 정확도**(Fit3D s07–s11, 같은 렙의 모캡 대비 |오차| 중앙값, 실제 중력; 원래 → C1 → C2):

### B. 가설
- rc1 기준이 느슨해진 이유는 "출처별 p99 중 가장 느슨한 값"이라는 사전 등록 규칙 때문으로 본다.
  - 공개 Mendeley 정상 클립은 15 fps 복제, 블러, 덤벨 로우다. 그래서 XS 지표가 넓게 퍼지고, 그 꼬리가 기준을 정한다.
  - 원래 XS 무릎 모임 0.224는 Exercise3D P1의 꼬리에서 나왔다.
  - 확인 실험은 사람 검수 틀린 자세 데이터로 출처별 기준을 비교하는 것이다.
- C1·C2의 Fit3D 로우 손목·아래팔 오경보는 학습 피험자와 검증 피험자의 당김 방식 차이로 본다. 공개 조정에서 정한 기준(손목 앞 37°)이 Fit3D 트레이너(모캡 중앙 72°)와 달랐다.
- C1 몸통 계열은 **미해결로 따로 둔다**(조정자 지시). Exercise3D 측면에서 C1 몸통 오차가 10.4–10.7°로 원래 XS(1.8–2.5°)보다 크다. 해당 규칙은 C1 프리셋에서 꺼져 있다: row_hinge_shallow, row_torso_swing, row_standing_up, squat_hips_first, squat_torso_lean, 몸 기준 숙임.

### C. 바뀐 판단
- "기준값을 정상 렙 분포로 다시 정하면 된다"(S7·이전 계획) → **부족하다.** 오경보 상한은 얻지만, 검출 근거 없이 정하면 규칙이 사실상 꺼진다. 검출을 보장하려면 사람 검수 틀린 자세 데이터가 필요하다.
- S7 후보(held-out에서 뽑은 순환 값)는 Halpe26 공개 held-out에서 5%를 넘은 규칙이 있었다: pushup_shallow 38%, pushup_no_lockout 13%, squat_knee_valgus 11%, row_standing_up(Ex3D) 33%. 채택 근거로 쓰지 않는다.
- R1(로우 상체 숙임) "카메라-위 정의로 충분": 폰 기울기 검사가 없는 지금은 **틀린 판단이다.** 10° 기울면 ±11°가 틀린다.
- 무릎 모임 "정면 2D 기준 1.0": 3D로는 정상의 63–100%가 울린다. 쓰지 않는다.

### D. 데이터 신뢰도
- Fit3D: 진짜 3D 정답이지만 사선 40–90°뿐이다. 앱 게이트를 적용하면 푸시업·스쿼트 측면 규칙은 평가할 렙이 0이다. Halpe26 2D는 실험 A(RTMDet+mmpose)이고 앱 crop 추적 경로가 아니다. C1·C2는 s03–s05로 학습해서 그 피험자는 도출에 쓰지 않았다.
- 공개: 클립 good/bad는 저자 라벨이고, 키 라벨은 AI 2패스 합의(사람 검수 없음)다. 15 fps 복제, 블러, 연기한 틀린 자세다. 로우는 덤벨 로우다. 로우는 렙 카운트가 잘 안 돼서, 판정된 held-out 정상 렙이 12개뿐이다.
- Exercise3D: 정상 렙 오경보만 썼다. 푸시업 held-out 피험자가 없다. C2는 P1로 학습했다.
- AI 'other' 관찰을 새 키로 바꾼 매핑(사전 등록 regex): 합의 기준 squat_torso_lean held-out 10클립(측면 4·사선 4·정면 2), 팔꿈치 벌림 1클립, 킥백 0클립.
  - 조정자가 물은 "과도한 앞숙임" 스쿼트 클립은 한 패스라도 언급한 것이 bad 29개다(측면 13·사선 10·정면 6). 두 패스가 합의한 것은 14개다.
  - 앞숙임은 2D에서 시점에 따라 달라 보인다. 이번 3D 지표는 측면 게이트를 통과한 렙에서만 판정했다.
- 다음은 측정 불가(관절 없음)라 평가하지 않았다: 둥근 등·요추 굴곡, 손목 굽힘(손 관절 없음), 바 경로, 그립, 으쓱(3D). 뒤꿈치는 Halpe26 2D 발로만 잰다.

### F. 추천 (제안)
1. **지금 가는 가짜 경고부터.** 다음 키를 `enabledFeedbackKeys`(기본 전달)에서 빼는 것을 제안한다. 판정과 로그는 남는다.
   - 대상: squat_no_lockout, squat_knee_valgus, pushup_no_lockout, pushup_hip_pike, pushup_shallow, pushup_head_up.
   - rc1처럼 기준을 느슨하게 하는 것도 오경보는 줄이지만, 검출 근거가 없어 "사실상 끔"과 같다.
2. 새 키 14개와 뒤꿈치는 계속 **플래그 뒤 로그로만** 둔다. 정상 오경보는 대부분 5% 안이지만 검출 근거가 없다.
3. R1(로우 상체 숙임)은 둘 중 하나가 필요하다.
   - (a) `BPT_3D_GRAVITY`를 기기에서 검증하고 켠다.
   - (b) 몸 기준(렙 평균 엉덩이각) 정의로 바꾼다. Fit3D에서는 오차 3°(C1)이고 카메라 기울기와 무관하다.
4. **사람이 검수한 틀린 자세 데이터.** 순서대로 제안한다.
   - (a) Mendeley held-out bad 클립을 트레이너 1명 또는 팀원 2명이 독립으로 렙·키 라벨한다(κ 보고). 촬영 없이 가장 빠르다.
   - (b) 직접 촬영. 4명 이상, 폰 세로·측면, 키마다 틀린 세트 6–8렙과 같은 사람의 정상 세트, 사람 2명이 렙 라벨. 새 키(상체 숙임 부족·무릎 폄/굽힘·팔꿈치 벌림·몸통-정강이)를 포함한다.
   - (c) Fitness-AQA·QEVD 접근 신청(사용자 계정 필요).
5. 모델: C1·C2는 대부분 지표 오차를 3–5배 줄인다. 다만 손목 지표와 C1 몸통(Exercise3D 측면)은 남은 문제다. 판정 기준은 모델을 바꾸면 다시 도출해야 한다(모델별 설정 유지).

## 분석 정의 보충 (2026-10-20 21:35, held-out 결과를 계산하기 전)
- **Fit3D의 "위" 방향.** 앱 정의는 카메라 −y이고 폰을 세워 둔다는 전제가 붙는다. Fit3D 카메라는 약 11° 아래로 기울어 있다(카메라마다 외부 파라미터로 측정, 예: 50591643 11.4°). 그래서 Fit3D의 카메라 −y는 앱 조건이 아니다. 폰을 세운 앱의 카메라 −y는 실제 중력과 거의 같으므로, Fit3D의 주 분석(도출·오경보)에는 **실제 중력**을 쓴다.
  - Fit3D 카메라-위 값은 "카메라가 11° 기울면 지표가 얼마나 틀리나" 표(R1, `BPT_3D_GRAVITY` 판단)에만 쓴다.
  - 근거: 조정 피험자 s03–s05 모캡 로우의 렙 평균 몸통각이 카메라-위로는 7–74°(p1–p99), 중력으로는 S7과 같은 40–63°대였다. 카메라마다 ±8–11°씩 엇갈렸다.
- **모캡 행은 앱 모델이 아니다.** 판정(근거 있음/약함/끄기)은 원래 XS·C1·C2에만 붙인다.
- **squat_heel_rise(Halpe26 발, 2D)를 평가에 더했다.** 사전 등록 밖이고, 사용자 Halpe26 결정 뒤에 추가했다. 기존 규칙 그대로 모든 시점에서 판정한다.
  - 3D 판정 경로에서 이 규칙을 쓰려면 2D heelToe를 3D 표본에 넘겨야 한다. 높이와 같은 "2D 보조 신호" 방식으로 Swift와 Python을 둘 다 고쳤다. 기본값은 여전히 꺼짐이다.
