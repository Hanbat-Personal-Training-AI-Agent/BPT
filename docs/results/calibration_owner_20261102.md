# Calibration account and lifetime ownership — 2026-11-02

This change prevents a late body-scan/profile/calibration response from being attached to a different account or a later login of the same account. `AuthSessionLease` checks the notifier instance, account ID, login generation and disposal. Logout invalidates it synchronously before persistence awaits; ordinary same-account token refresh retains it.

`recordBodyScan` and background `tryAutoLogin` ignore late success/error/401 callbacks. `updateProfile` and `saveOnboarding` recheck the lease after local persistence before issuing a mutation. A delayed `deleteAccount` completion cannot clear another account's active session. A small persistence queue keeps an already-started old logout clear ordered before new login credentials; it does not introduce another credential cache.

Calibration result and personal-reference keys are account-scoped v2 keys. Unowned v1 data is preserved and never automatically assigned to a new account. Captured store leases reject late poll completions and stale reads/writes, including A→B→A login. Setup UI loads/references use the captured store; an account switch disposes the experimental native setup view so its creation-time body dimensions are not retained.

The analyzing screen captures its service and session once. Upload acceptance, job polling, model download and native mesh preparation all recheck ownership; late prepared meshes are released. Anonymous local onboarding can continue with an empty placeholder and preserved photographs, but cannot upload or adopt a result. Authenticated work invalidated by account change cannot navigate an old result into the new account. The calibration upload token provider is bound to the same captured lease, preventing a delayed bundle read from obtaining the new account's token.

Shared result validation requires centimeter bone units and finite, positive numeric dimensions; malformed body maps/segments, nonfinite height, invalid beta types/lengths and nonfinite references are rejected without overwriting a valid saved result. Safe skeleton/rest-pose provenance, `appDefinitionDiffers`, and fitting height/reprojection evidence are preserved. Missing, malformed or entirely null quality is explicitly unavailable, never an accuracy probability. Signed mesh URLs and debug payloads are not persisted. These dimensions remain reference-only measurements; no fitting/form accuracy is claimed.

Validation covers stale scan/profile callbacks, delayed storage clear/save, A→B→A leases, provider replacement, per-account results/references and legacy preservation, invalid units/types/NaN/Infinity, missing quality, stale tracked jobs, delayed upload/poll/download/native preparation and native mesh release. The setup-flag owner suite passed 14 tests; the mesh-flag analyzing suite passed 15 tests. Targeted Flutter analysis found no issues. Default upload/setup/scan/delete/login regression checks and `git diff --check` were also run; final counts are recorded with the commit handoff.

Scope at this freeze: no flag/default/model/backend/deployment change; all tests use synthetic local mocks, no actual photos/models, API upload or device job. Separate follow-ups are required for (1) AuthService's login/signup token commit and opt-in transport retry guard, and (2) carrying capture-start ownership through the native scan callback. This freeze alone is not a claim that all account transport or capture provenance races are closed.

## Follow-up: auth token commit and opt-in request ownership

`AuthService.login/signUp` now accept an optional local `canCommit` predicate. The notifier supplies its login generation; the service validates it immediately before committing response tokens. Late A success/failure after B and logout-during-login cannot replace B's transport token, persisted credentials or notifier state. A stale signup returns a session-changed message instead of pretending success to the onboarding caller. Direct service calls without the optional predicate retain existing behavior; production source search found the notifier is the only login/signup service caller and both calls supply the predicate.

The public transport hook is `Options(extra: {ApiClient.sessionGuardKey: () => capturedLease.isCurrent})`, key `bpt.sessionGuard`. It is evaluated before sending and before/after refresh or retry; false, invalid or throwing predicates cancel with local `STALE_SESSION`. The callback remains local RequestOptions metadata and is never serialized into headers/body/query/logs. Old A mutations cannot be retried with B's newer token. Same-session token refresh remains allowed. The notifier binds profile refresh, body-scan, onboarding/profile mutations and account deletion to their captured leases. No global request/credential redesign was introduced; unguarded unrelated API callers retain their previous behavior and require explicit opt-in by their owners.

Ten real-adapter synthetic transport tests passed, including reversed A/B login and signup responses (success/failure), pending logout, pre-send cancellation, delayed A401→B, account change during pending refresh, same-A refresh success, and direct service compatibility. The existing token-refresh/signup/owner regression run passed 30 tests with one setup-flag-only skip. No live backend calls were made. The capture-start envelope remains a separate follow-up at this point.

An active profile/body-scan response with an unexpected owner now invalidates the mismatched cached session rather than keeping a cached A identity paired with another server identity. The additional owner regression run passed 14 tests with one setup-only skip, and targeted analysis reported no issues.
