## 5. 방법 A: 사람이 단 COCO 키포인트로 회귀 정의 시험 (`scripts/coco_smpl_coco17_check.py`, Fit3D 이미지 없음)

실행: Home `~/bpt-runs/fit3d-label-verify/A-coco-smpl-20261018-0215/` (`manifest.json`에 입력 sha256·명령·코드 sha, 결과 `result.json`은 집계만).

- 사람: COCO 2017 키포인트(사람이 단 값, v=2 보이는 점만, v=1은 따로).
- 피팅 ① **EFT COCO2014-Val-ver10**(사람이 걸러 낸 10,510명, SMPL). EFT 코드(`eftFitter.py`)를 확인한 결과 EFT는 COCO 키포인트에
  SPIN 관절 정의(어깨·팔꿈치·손목·무릎 = SMPL 관절 중심, 얼굴 = SMPL 정점)로 맞췄고, **COCO 엉덩이는 끄고**, 발목은 정강이 방향만 썼다.
  → EFT에서 **엉덩이는 순환이 아니다**(정의 시험이 됨). 어깨·얼굴·팔꿈치·손목·무릎은 native 정의로 맞춘 것이라 native에는 순환(시험 아님).
- 피팅 ② **DensePose 재피팅**: 같은 사람 중 DensePose-COCO 표면 대응점이 있는 2,551명을, 키포인트 항 없이 표면점(사람당 중앙값 135개)만으로 다시 맞춤
  (EFT에서 시작, 자세 사전 = EFT 자세와의 L2, 가중치 λ 100/10/1로 3번). 모든 관절이 같은 조건이 되고, 팔다리는 독립된 피팅 품질 점검이 된다.
- 정의(같은 행렬, Fit3D 경로의 smplx2smpl 단계만 없음): gvhmr = WHAM/GVHMR `J_regressor_coco`, native = SMPL 관절 중심 + 얼굴 정점, h36m = `J_regressor_h36m`.
- 투영 점검(사실): EFT 약원근 투영은 `n = s·X + t`(EFT `convert_smpl_to_bbox`) 순서가 맞음 — 피팅된 관절의 평균 잔차 (−0.002, −0.003)박스, 다른 순서는 (−0.003, −0.019).
  EFT json의 키포인트 = COCO 키포인트(차이 0 px). DensePose V 방향: 그대로가 맞음(EFT 시작점 잔차 0.028 vs 뒤집으면 0.046).
- 숫자: 오차 = 사람 COCO 점과의 거리 ÷ COCO 박스 긴 변, 치우침 = (사람 − 라벨)을 라벨 몸통 축으로 본 평균 ÷ 몸통 길이(위 + = 사람 점이 라벨보다 위, 옆 + = 사람 기준 오른쪽).
  "팔다리 양호" = 보이는 팔다리 점(≥4개) gvhmr 오차 중앙값 < 0.05인 사람만(EFT 10,362/10,510명, DP 2,498/2,551명).

- **EFT 피팅**: 키포인트에 맞춘 피팅이라 어깨·얼굴·팔꿈치·손목·무릎은 native 정의에 순환 → 그 관절의 native 숫자는 시험이 아님. 엉덩이만 독립. SMPL(Fit3D는 SMPL-X → smplx2smpl)이고 약원근 투영.
- **DensePose 재피팅**: 키포인트 없이 맞췄지만 EFT에서 시작하고 자세 사전이 EFT로 당김(λ를 바꿔도 결과가 거의 같아 영향은 작음). 표면점이 듬성듬성해서 몸 전체가 +.02–.03 어긋남 → 팔다리 맞춤(anchored)으로 보정해 같이 봤다.
- **모델 합의(B)**: 정답 아님. 네 모델 모두 같은 COCO 라벨로 학습했으므로 COCO 규약은 잘 대변하지만 공통 습관도 함께 가진다. 엎드림·가려짐에서 약해짐. RTMPose-l은 앱과 같은 계열.
- **Fit3D SMPL-X 피팅**: 실루엣 IoU .754, 프레임별 β 변화로 어깨폭이 7% 흔들림(§3–4). 라벨 오차에는 정의 차이와 피팅 오차가 섞인다.
