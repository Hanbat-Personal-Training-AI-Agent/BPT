# Fit3D SMPL-X → COCO17 라벨 17점 검증 (진행 중)

날짜: 2026-10-18 · 브랜치 `ai/fit3d-label-verify`(`ai/rtmpose-ft` 60da39c 위, 그 브랜치의 검사 스크립트를 재사용) · 관련: D-C-09, D-C-10, 2026-10-17 STOP 지시

**상태: 검증 미완료.** 사용자의 COCO 정의 수동 기준점(아래 §5)과의 비교를 아직 돌리지 않았다. 이 문서에는 라벨 판정이 없다.
아래 내용은 사실(숫자로 확인함)과 가설(해석)로 나눠 적었다. 모캡 관절 중심과의 3D 거리는 정답 기준으로 쓰지 않는다.
RTMPose-m(앱 모델)은 비교 참고일 뿐 정답이 아니다.

Fit3D 프레임, 겹침 그림, 프레임별 2D 좌표는 저장소에 넣지 않는다(라이선스). Claude는 Fit3D 이미지를 열지 않았다. 이 문서의 숫자는 모두 집계값이다.

## 1. 비교한 라벨 출처

모든 출처는 Fit3D 공식 프레임별 SMPL-X 파라미터(회전 행렬, 프레임별 β·표정)를 `smplx` 라이브러리 `SMPLXLayer`(0.1.28)에 넣어 만들고,
공식 카메라(외부 파라미터 + `intrinsics_w_distortion` + Fit3D/H36M 왜곡 모델)로 원본 900×900 영상에 투영했다.

| 이름 | 만드는 법 | 얼굴 | 비고 |
|---|---|---|---|
| gvhmr | GVHMR `SmplxLiteCoco17` = `smpl_coco17_J_regressor` [17×6890] × `smplx2smpl_sparse` [6890×10475] | 있음 | WHAM `J_regressor_coco` × `smplx2smpl.pkl`과 최대 차이 2.4e-8(같은 행렬). 표면 정점 가중 평균(관절당 정점 3–15개) |
| native | smplx 라이브러리 관절: 몸 관절 중심(엉덩이 1/2, 어깨 16/17 …) + 얼굴 정점(코 9120, 눈 9929/9448, 귀 616/6) | 있음 | COCO 이름으로 SMPL-X 관절을 고르는 방식(mmpose `ubody_smplx_to_coco.py`, 여러 HMR 코드와 같은 방식) |
| h36m | WHAM/SPIN `J_regressor_h36m` × smplx2smpl | 없음 | 몸 12점만 |
| mocap | Fit3D `joints3d_25` | 없음 | 몸 12점만 |

조사만 하고 비교하지 않은 것: mmhuman3d/SPIN/VIBE/PARE/4D-Humans의 COCO 매핑(SMPL 관절 중심 + 추가 회귀 행렬. native·h36m과 같은 종류),
CameraHMR·SMPLest-X의 회귀 행렬(공개 파일을 확인하지 못함). 새 회귀 행렬은 학습하지 않았다.

## 3. 지금 측정할 수 있는 것 (`measure`, 8명 × 5운동 × 카메라 4대, 5프레임마다, RTMPose는 10프레임마다)

- 좌우 축 뒤집힘: 라벨의 (왼−오) 방향이 모캡 골반(또는 어깨) 좌우 방향과 반대인 프레임 비율. 발목 3.6%·무릎 0.7%는 두 발이 거의 겹치는 자세에서 나오는 것으로 추정(가설). 모캡 매핑 좌우도 SMPL-X 관절과 비교해 100% 같은 쪽(사실).
- 가려짐: 정점 점찍기 깊이 버퍼 + 12 cm 여유. 엉덩이·어깨·얼굴처럼 몸 속이나 머리 뒤쪽에 있는 점은 이 방식으로 거의 다 "가려짐"으로 나와서 **이 열은 팔다리에만 의미가 있다**(가설, 수동 기준점의 "가려짐" 표시로 다시 볼 것).
- 3D 뼈 길이 변동계수(gvhmr, 중앙값/최대): 어깨 폭 7.1%/12.6%, 엉덩이 폭 4.3%/6.5%, 몸통 5.9–6.7%/11–13%, 위팔 1.3–1.6%, 아래팔 2.2–3.2%, 허벅지 0.6–2.6%, 정강이 0.4–0.6%, 눈 사이 0.3%, 귀 사이 0.4%.

- 평균 길이(mm): 엉덩이 폭 gvhmr 205, native 119, h36m 294, mocap 272. 어깨 폭 gvhmr 314, native 306, h36m 294, mocap 281. 출처마다 엉덩이 정의가 크게 다르다(사실).

## 4. SMPL-X 피팅 자체 (`fitcheck`, 320장 = 8명 × 5운동 × 렙 위·아래 × 카메라 4대, 1장은 사람 마스크 없음)

메시 실루엣(모든 면 채움, 왜곡 포함 투영) vs RTMDet-Ins-m 사람 마스크(COCO, Apache-2.0, 참고용).

| IoU 중앙값 (p10, 최소) | 정밀도(메시가 마스크 안) | 재현율(마스크를 메시가 덮음) | 경계 거리 중앙값 / p90 (÷ 박스) |
|---|---|---|---|
| 0.754 (0.714, 0.658) | 0.940 (p10 0.901) | 0.800 (p10 0.744) | 0.033 / 0.098 |

운동별 IoU: 스쿼트 0.741, 푸시업 0.784, 다이아몬드 0.782, 바벨 로우 0.741, 데드 로우 0.734.

가설: 옷·머리카락·신발(맨몸 SMPL-X가 덮지 않음)과 마스크 경계가 원인. 바벨이 마스크에 섞였을 수도 있다. 피팅이 크게 어긋났다는 증거는 아니지만, 수 cm 수준의 정확도를 이것으로 보장할 수는 없다.

## 5. 수동 COCO 기준점 (준비 완료, 사용자 작업 대기)

- 프레임 40장: 8명 × (스쿼트 위·아래, 푸시업 위·아래, 바벨 로우 아래), 카메라 4대 순환, 렙 안 위치는 고정 시드 무작위. 반복 5장(f01, f09, f17, f25, f33을 다시 찍기) = 총 45장.
  처음 8장이 사람 8명을 하나씩 덮도록 순서를 정해 일부만 해도 사람별로 고르게 남는다. 다이아몬드 푸시업·데드 로우는 빠짐(40장 상한).
- 찍기 페이지 `tools/fit3d_annot/index.html`(저장소에는 페이지만, 프레임은 로컬 `~/Documents/bpt-fit3d-annot/frames/`):
  라벨은 보여 주지 않음, 관절마다 한국어 COCO 정의, 불확실·안 보임 표시, 되돌리기, 확대/이동/돋보기, 브라우저에 자동 보관, JSON 내보내기·불러오기.
  합성 SVG 그림(Fit3D 아님)으로 Chrome에서 실제 클릭을 해서 확인: 기본·확대·이동 후 클릭 좌표 오차 ≤ 1 px, 불확실/안 보임/되돌리기, 반복 프레임이 원래 프레임 클릭을 보여 주지 않음, 새로고침 후 유지, 내보낸 JSON 형식.
- 비교 스크립트 `scripts/compare_fit3d_manual_coco17.py`: 관절 17개 × 출처(gvhmr, native, h36m, mocap, rtmpose_m)별 px·박스 대비 오차, PCK@0.05/0.1,
  몸 기준 치우침(위/옆), 좌우 뒤바뀜, 반복 클릭 재현성. `--selftest`(합성 데이터) 통과, 실제 candidates.json 형식으로도 실행 확인.
- 겹침 그림(사용자가 찍기를 끝낸 뒤 볼 것): `~/Documents/bpt-fit3d-review/label_verify.html`(왼쪽 ● 라벨 + RTMPose, 오른쪽 ● 라벨 ○ 모캡 □ SMPL-X 관절 중심).
