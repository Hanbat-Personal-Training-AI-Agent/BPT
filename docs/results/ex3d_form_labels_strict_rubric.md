- 이번 2차 라벨은 **PT 엄격 모드 기준값의 근거**다. 같은 132 물리적 렙을 실제 PT가 코칭할 수준으로 다시 본다.
- **라벨러는 AI(Claude)다. 사람 라벨이 아니다.**
  - 운동마다 새 Claude 에이전트 하나가 라벨한다.
  - 라벨러는 1차 라벨, 앱 경고, 앱 지표를 보지 않는다. 이 루브릭과 영상 이미지만 본다.
  - 렙마다 라벨러는 하나다.
- Exercise3D는 팀 자체 데이터셋이고, 사용자가 2026-10-23 프레임 열람을 허락했다.
  - 이미지는 git, 외부 서비스, Codex에 올리지 않는다.
  - Fit3D 이미지는 열지 않는다.

## 1. 등급 (항목마다 하나)
| 등급 | 값 | 뜻 |
|---|---|---|
| 명확한 오류 | `error` | 1차 루브릭의 error와 같은 선. 앱이 경고해야 할 수준이다. |
| PT가 지적할 개선점 | `tip` | 위험하지는 않지만 PT라면 "조금 더 ~하자"라고 짚을 차이가 눈에 보인다. |
| 좋음 | `good` | PT가 짚을 것이 없다. |
| 판단 불가 | `unsure` | 어느 카메라로도 판단할 수 없다(가림, 옷, 시점, 해상도). 추측하지 않는다. |

- 경계값 근처에서는 가까운 쪽을 고르고 confidence를 `low`로 둔다.
- confidence는 `high` / `med` / `low`다. `unsure`이면 비운다.
- notes에는 눈대중 값을 적는다. 예: "허벅지 약 5° 위", "몸통 변화 약 12°", "팔꿈치 몸통에서 약 60°". 표의 각도와 거리는 눈대중 기준이다.

## 5. 기준값 후보 규칙 (라벨 커밋 뒤 계산, 미리 정함)
### 데이터
- rules-calib Python 앱 경로의 렙 지표다: 원래 XS, m Halpe26 입력, `20261020-pubpy-h26-tune-ex3d`, 39클립. 13세트 전부를 쓴다.
- 앱 게이트를 통과한 렙만 쓴다.
  - 시상면 지표는 측면 게이트를 통과한 렙이다.
  - 무릎 모임은 정면 분기 렙이다.
- 물리적 렙 라벨은 1차 CSV의 `replay_rep` 대응으로 카메라 렙에 붙인다.
- 같은 물리적 렙이 카메라마다 한 표본이 된다. 유효 표본 수는 물리적 렙 수로 따로 적는다.

### 모드별 기준값
- 묶음은 G = good, T = tip, E = error다. unsure는 뺀다.
- 지표가 클수록 나쁜 경우(위꼬리)로 적는다. 작을수록 나쁜 지표는 방향만 뒤집는다.

| 모드 | 기준값 | 데이터가 모자랄 때 |
|---|---|---|
| **PT 엄격** | G와 (T ∪ E)를 가장 잘 가르는 값(Youden J 최대) | 두 묶음 중 하나가 물리적 렙 5개 미만이면 G의 p90을 쓴다. 이 값은 "잠정"으로 표시한다. |
| **표준** | (G ∪ T)와 E를 가장 잘 가르는 값 | E가 물리적 렙 5개 미만이면 (G ∪ T)의 p99를 쓴다. tip 렙에서는 거의 울리지 않는 값이다. |
| **여유** | rules-calib rc1 값(정상 렙 p99, 출처 중 가장 느슨한 값; 원래 XS) | rc1이 없으면 "없음"으로 둔다. |

- 표마다 묶음별 분포(물리적 렙 수, 카메라 렙 수, 중앙값, p10–p90)를 같이 싣는다.
- 각 기준값의 Ex3D 발화율도 같이 싣는다. 대상은 G, T, E 각각이다.
- 세 값의 순서가 엄격 ≤ 표준 ≤ 여유(위꼬리)가 아니면 그대로 싣고 이유를 적는다.
- 측정 가능성이 "불가"인 항목은 기준값을 내지 않는다. 대신 "측정 불가, 필요한 신호"로 따로 정리한다.
- 모든 값은 **제안**이다. 앱 기본값이나 프리셋을 바꾸려면 사용자 승인이 필요하다.
