# rtmpose-ft: COCO17 학습 라벨 관절별 검증 (5단계 판정)

날짜: 2026-10-17 · 트랙 ai/rtmpose-ft · 결정 D-C-08

Fit3D·Exercise3D 원본 이미지와 겹침 그림은 라이선스 때문에 저장소에 넣지 않는다. 여기에는 집계 숫자만 있다.
겹침 그림(라벨 초록, 현재 앱 모델 빨강)은 Home에만 있다: `~/rtmft/verify/fit3d/sheets/<s>_<운동>.jpg`(사람 8명 × 운동 5개,
렙 위·아래 × 카메라 4대), `~/rtmft/verify/fit3d/render_*.jpg`(카메라 4대 확대), `~/rtmft/verify/ex3d/sheets/`.
**이 그림들은 사람이 직접 봐야 한다.** 2026-10-17부터 Claude는 Fit3D·Exercise3D 이미지를 열지 않는다(모델 API로 전송되면
외부 공유가 되어 Fit3D 라이선스 위반). 그 전에 s03 스쿼트·푸시업 그림 몇 장이 전송된 사실은 사용자에게 보고되어 있다.

## 1. 라벨 만드는 법(조사 결과, 1단계)

| 도구 | 하는 일 | 라이선스 | 필요한 파일 | 판단 |
|---|---|---|---|---|
| GVHMR `SmplxLiteCoco17` | SMPL-X 메시 → SMPL 정점(희소 행렬) → COCO17 회귀 행렬 [17×6890] | 연구·비영리 전용 | SMPL-X 모델(`SMPLX_*.npz`, 계정 필요) | SMPL-X 없어서 Fit3D 메시 단계 막힘 |
| WHAM `J_regressor_coco.npy` | GVHMR 것과 바이트 단위로 같은 COCO17 회귀 행렬 | MIT | SMPL 정점만 | Exercise3D(SMPL) 의사정답에 사용 |
| mmhuman3d / SPIN / VIBE / PARE / 4DHumans | COCO 엉덩이·어깨를 SMPL 관절 중심에서 가져옴 | 각자 | SMPL | COCO 표면 정의가 아님(D-C-02와 같은 문제) → 안 씀 |
| Fit3D GHUM(gpp) | GHUM 파라미터 | Fit3D | GHUM 모델 | GHUM→COCO17 회귀가 없음(새 변환 모델 = 금지) |

- **사용자에게 필요한 것: SMPL-X 모델 다운로드(smpl-x.is.tue.mpg.de 계정).** 받아서 Home에 `SMPLX_NEUTRAL.npz`(+MALE/FEMALE)를
  두면 Fit3D 공식 SMPL-X 파라미터 → 메시 → COCO17 라벨을 만들고 아래 검사를 다시 돌린다. 그때까지 판정은 모캡 투영 관절만 다룬다.

## 2. Fit3D 모캡 투영 라벨 (정답, 160영상 = 8명 × 5운동 × 카메라 4대)

`joints3d_25`(모캡 3D) → 공식 카메라(외부·내부 파라미터 + 렌즈 왜곡)로 원본 영상에 투영. 도구 `scripts/check_fit3d_coco17_labels.py`.

쉬운 말 풀이:
- **모델과 거리**: 현재 앱 모델(RTMPose-m)과 라벨 사이 거리 ÷ 사람 박스 크기(0.05 = 박스의 5%). 모델은 정답이 아니다.
  거리가 크면 "눈으로 볼 곳" 표시일 뿐이다.
- **10% 넘는 비율**: 모델과 거리가 박스의 10%를 넘는 프레임 비율(전체 프레임 합).
- **치우침(위/옆)**: 모델 − 라벨의 평균 방향. 몸통 길이 단위. 0에서 멀면 라벨이 체계적으로 다른 점을 가리킨다(정의 차이).
- **좌우 뒤바뀜**: 라벨 좌우를 바꾸면 모델과 거리가 절반 이하가 되는 프레임 비율.
- **흔들림**: 라벨 2D 궤적의 2차 차분(픽셀, 50 fps), 상위 1%.
- **화면 밖**: 투영점이 이미지 밖인 비율.

(거리·치우침·흔들림은 영상별 값의 중앙값, "10% 넘는 비율"과 뒤바뀜은 전체 프레임 합.)

추가 검사:
- **영상-모캡 시간 맞춤**: 손목·발목 기준 모델 거리가 가장 작은 시간 차이가 0프레임인 영상 116/160, ±1프레임 39, ±2–3 5 → 맞음(50 fps에서 1프레임 = 20 ms).
- **카메라 간 일관성**: 라벨은 하나의 3D 모캡을 4대 카메라에 투영한 것이라 정의상 일치한다. 공식 왜곡 모델을 쓴다.
- **3D 뼈 길이 변화(라벨만, `--bones`)**: 위팔·아래팔·허벅지·정강이 길이 변동계수 0.0000(40시퀀스 전부) → joints3d_25는 길이 고정 골격이다.
- **3D 관절 속도 급등(라벨만)**: 프레임당 50 mm(= 2.5 m/s) 넘는 어깨 점프가 40시퀀스 중 3개에서 1–2프레임씩, 총 5프레임(모캡 순간 튐, 추정).
  학습 영향은 무시할 수준(약 4만 프레임 중 5).
- **모델과 크게 다른 영상(10% 넘는 비율 > 20%)**: 팔다리 관절은 대부분 푸시업·다이아몬드 푸시업(엎드린 자세, 앱 모델이 약한 자세)에서 나옴.
  엉덩이는 모든 운동에서 84–106영상 → 자세가 아니라 정의 문제.

## 3. Exercise3D SMPL 피팅 → COCO17 (의사정답, Sapiens 유래, 상태 REVIEW, 학습 금지 D-C-01)

SMPL v1.1.0 메시 → WHAM COCO17 회귀 → 공식 카메라. 39영상. 비교 대상은 Sapiens2 2D 라벨(이것도 정답 아님).

| 관절 | Sapiens2와 거리 중앙값 | Sapiens2 기준 PCK@0.05 (박스 5% 안 비율) |
|---|---|---|
| 무릎·발목·팔꿈치 | 0.022–0.035 | 0.91–1.00 |
| 손목 | 0.041–0.055 | 0.49–0.63 |
| 어깨 | 0.033–0.040 | 0.70–0.74 |
| 엉덩이 | 0.058–0.063 (좌우로 0.07–0.09 몸통 더 넓음) | 0.32–0.41 |
| 얼굴 5점 | 0.044–0.062 | 0.16–0.65 |

원인: Exercise3D 피팅이 SMPL 관절 중심을 Sapiens의 COCO 표면 엉덩이·어깨에 맞춰 놓아서, 그 메시에서 다시 COCO 표면점을
뽑으면 차이가 두 번 들어간다. Exercise3D는 평가용으로 계속 Sapiens2 2D를 쓴다.

## 4. 관절별 판정 (5단계)

판정 기준(숫자만 근거, 그림은 사용자 확인용): 정의가 COCO와 같음 + 모델과 거리 중앙값 ≤ 0.04 + 체계적 치우침 ≤ 0.06 + 뒤바뀜 < 1% + 흔들림 p99 < 2 px → 검증.

| 관절 | Fit3D (정답) | 학습 가중치 | Exercise3D (의사정답) | 근거 |
|---|---|---|---|---|
| 팔꿈치 ×2 | **검증** | 1 | 평가만 가능(학습 금지) | 거리 0.025–0.035, 치우침 작음, 뒤바뀜 0.04% 이하 |
| 손목 ×2 | **검증** | 1 | 의심 | 거리 0.018–0.020 |
| 무릎 ×2 | **검증** | 1 | 평가만 가능 | 거리 0.028–0.035 |
| 발목 ×2 | **검증** | 1 | 평가만 가능 | 거리 0.032–0.034, 위 치우침 0.05–0.08(발목 마커 위치 차이, 추정) — 기준 안 |
| 어깨 ×2 | **의심** | 0 | 의심 | 거리는 작지만 모캡 어깨는 관절 중심(D-C-02), 오른 어깨 옆 치우침 0.041, SMPL-X 메시 확인 전 보류 |
| 엉덩이 ×2 | **기각** | 0 | 기각 | 모캡 엉덩이 = 관절 중심, 위 치우침 0.11–0.17 몸통, 28–39% 프레임이 10% 넘음 |
| 얼굴 5점 | **라벨 없음** | 0 | 기각 | Fit3D 머리 마커는 COCO 코·눈·귀가 아님 |

- 가중치 0인 관절은 COCO train2017 섞기(에폭마다 절반)로 COCO 정의를 유지한다.
- SMPL-X가 오면: 메시 COCO17 어깨·엉덩이·얼굴을 같은 검사(모캡 팔다리와 거리, 카메라 간, 뒤바뀜, 흔들림)로 다시 판정한다.
- **사용자 확인 요청**: 위 Home 경로의 그림에서 팔꿈치·손목·무릎·발목 초록 점이 관절 위에 있는지, 특히 푸시업·다이아몬드
  푸시업의 가려진 쪽 팔다리를 확인해 달라. 문제가 보이면 그 관절을 "의심"으로 내리고 다시 학습한다.
