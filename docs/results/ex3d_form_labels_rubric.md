# Exercise3D 렙별 자세 라벨 — 루브릭 (ai/ex3d-form-labels, 2026-10-23)

이 문서는 **렙별 모델 경고를 보기 전에** 커밋한다. 커밋 뒤에 바꾸는 것은 오탈자와 문장 보강뿐이다. 기준·절차·비교 규칙을 바꾸면 그 사실과 이유를 결과 문서(`ex3d_form_labels.md`)에 따로 적는다.

## 0. 왜, 누가
- rules-calib(ai/rules-calib)은 Exercise3D의 모든 렙을 "정상"으로 놓고 기준값(P1 = 도출)과 오경보율(P2·P3 = 평가)을 냈다. Exercise3D는 운동선수가 아닌 팀원이 찍었으므로 실제 자세 오류가 섞여 있을 수 있다. 그러면 기준값이 느슨해지고, 맞게 잡은 경고가 오경보로 세어졌을 수 있다. 이 가정을 렙마다 눈으로 확인한다.
- **라벨러는 AI(Claude) 하나다. 사람 라벨이 아니다.** 사람 검수나 2차 라벨러가 없어 라벨러 간 일치도(κ)는 낼 수 없다. 결과는 "AI 시각 라벨 기준"이라는 단서를 항상 붙인다.
- Exercise3D는 팀 자체 데이터셋이고, 사용자가 2026-10-23 프레임 열람을 허락했다("너가 봐도됨, 우리가 만든 데이터셋"). 이미지·시트는 git과 외부 서비스에 올리지 않고 `~/bpt-data/ex3d_label_sheets/`에만 둔다. Fit3D 이미지는 열지 않는다.

## 1. 블라인드 절차
1. 이 루브릭을 커밋한다.
2. 렙 경계와 대표 프레임은 **경고 필드를 뺀 표**(렙 구간, 2D 키포인트, 동기화 정보)로만 고른다. 경고 필드(`warnings`, `warnings_2d`, `warnings_3d`, `spoken`, `grades`, `warning_rep_counts`, 세트 `events`)는 별도 파일로 떼어 두고, 라벨을 모두 쓰기 전에는 열지 않는다.
3. **라벨 CSV를 먼저 커밋**하고, 그 뒤에 경고와 맞춰 본다.
4. 이미 본 정보(정직하게 적어 둔다):
   - `rules_calib.md`의 집계. 예: 현재 기준값 Ex3D 오경보 squat_no_lockout 19%, squat_knee_valgus 29%. 렙 단위 정보는 없다.
   - squat_0000_cam1의 세트 집계 한 줄. 기기 실행 `warning_rep_counts`(squat_no_lockout 5렙)와 2D 재생 세트 이벤트(squat_no_lockout 1건)를 데이터 구조를 확인하다가 봤다. 어느 렙인지는 보지 않았다.
   - 첫 렙 하나의 이벤트 구조(squat_0000_cam1 렙 1: 경고 없음, praise_good).

## 2. 증거(시트)
- **물리적 렙 단위로 본다.** 세 카메라는 같은 세트를 동시에 찍었다(`sync.json` 상태 PASS, 세 클립의 프레임 수가 같음). 그래서 한 물리적 렙은 세 카메라에 같은 프레임 번호로 나온다.
- **물리적 렙의 기준점**은 `outputs/rep_validation/gt.json`의 `rep_frames`다(Sapiens 삼각측량 라벨에서 센 렙 극점. 렙 수는 맞고, 구간 정답은 아니다).
- 렙마다 시트 한 장을 만든다. 행은 cam1·cam2·cam3, 열은 네 시점이다. 같은 프레임 번호를 세 카메라에서 뽑는다.
  - 스쿼트·푸시업: T0 시작(위), T1 바닥(가장 깊은 곳), T2 올라오기 초반(T1에서 T3까지의 1/3 지점), T3 끝(위, 락아웃).
  - 로우: T0 시작(팔을 편 채 바가 가장 낮은 곳), Tm 당기는 중간(T0과 T1의 중간), T1 당김 정점(바가 가장 높은 곳), T3 끝(다시 가장 낮은 곳).
- 대표 프레임은 가장 측면에 가까운 카메라의 2D 키포인트로 고른다(기기 실행 Halpe26).
  - 스쿼트 바닥은 엉덩이가 가장 낮은 프레임이다.
  - 푸시업 바닥은 어깨가 가장 낮은 프레임이다.
  - 로우 정점은 손목이 가장 높은 프레임이다.
  - 위·시작·끝은 이웃한 극점 사이에서 반대쪽 극값을 쓴다.
  - 키포인트는 그림에 겹쳐 그리지 않는다. 사람 주변만 잘라 키운다.
- 세트마다 개요 시트도 한 장 만든다. 가장 측면 카메라에서 모든 렙의 T1과 T3를 나란히 놓은 것이다. 같은 세트 안의 상대 비교(앞 렙보다 덜 내려감·덜 폄)에 쓴다.
- 시트로 판단이 안 되면 그 렙의 프레임을 더 뽑아 본다(발 확대, 프레임 추가). 그 사실은 notes에 적는다.

## 3. 라벨 값
- **label**: `ok` / `error` / `unsure`.
  - 경계값 근처에서도 판단할 수 있으면 ok 또는 error를 고르고, confidence를 `low`로 둔다.
  - `unsure`는 어느 카메라로도 판단할 수 없을 때만 쓴다. 가림, 시점, 해상도 같은 이유다.
- **confidence**: `high` / `med` / `low`.
  - high: 맞는 시점 하나 이상에서 크기가 뚜렷하다.
  - med: 보이지만 크기가 경계 근처이거나, 사선 하나로만 보인다.
  - low: 잘 안 보이거나 경계값이다. 그래도 판정은 내린다.
- **cam_visible**(카메라마다): `yes` / `partial` / `no`. 그 카메라 하나만으로 이 기준을 판단할 수 있는지를 적는다(4절 표).
- **물리적 렙 라벨**은 그 기준을 보여 줄 수 있는 카메라에서 내린다. 카메라 사이에 보이는 것이 다르면 더 맞는 시점을 따르고 notes에 적는다.
- CSV 행은 클립(카메라) × 물리적 렙이다. 한 물리적 렙의 세 행은 label·confidence가 같고 cam_visible만 다르다.

## 4. 시점
- 각도는 `gt.json` `angle_deg`다(0° = 정측면, 90° = 정면 또는 정후면).
- 분류는 rules-calib과 같다: side ≤ 40°, diag 40–70°, front > 70°.
- 카메라 배치(2026-10-23 `views.png`로 확인):
  - 스쿼트·로우:
    - cam1 = 앞-옆 사선(17–37°).
    - cam2 = 반대쪽 앞-옆, 멀리(20–40°).
    - cam3 = 뒤쪽(52–81°).
  - 푸시업:
    - cam1 = 발 쪽(뒤, 70–88°).
    - cam2 = 머리 쪽 사선(25–48°).
    - cam3 = 측면(10–24°).

| 기준 | side(≤40°) | diag(40–70°) | front/rear(>70°) |
|---|---|---|---|
| 시상면 기준(깊이, 락아웃, 몸통 숙임, 엉덩이 먼저, 엉덩이 처짐·들림, 머리, 로우 반동·세움·당김) | yes | partial | no |
| 무릎 모임 | no(앞 사선 cam1은 partial) | partial | yes |
| 뒤꿈치 들림 | partial(발이 작음) | partial | partial(뒤에서는 뒤꿈치가 보임) |
| 으쓱 | partial | partial | yes |
| 손 위치(앞뒤) | yes | partial | no |
| 손 위치(너비) | no | partial | yes |

## 6. 비교 규칙 (라벨 커밋 뒤 계산)
- **비교 대상(주)**: 기기 실행의 렙 보고 `warnings`다. 실행은 Home `~/bpt-runs/lift-app/20261020-device-halpe-ab-a8b29f1-partial-20261021-103959/full_mhalpe26_r0`이다.
  - 조건: iPhone, 앱 a8b29f1, m Halpe26, 원래 XS, 중력 끔, `BPT_RULES` 없음 = 현재 기준값.
  - 이 실행은 D-M-04 이전이라 모든 키가 판정되고 보내진다.
  - 이 실행에 없는 클립은 같은 설정의 다른 기기 실행에서 가져오거나, 없으면 "기기 결과 없음"으로 둔다.
- **비교 대상(보조)**: rules-calib Python 앱 경로 지표(`20261020-pubpy-h26-tune-ex3d`, 원래 XS)다. 현재 기준값과 rc1 기준값을 적용한다. 오염 분석도 이 지표로 한다.
- **렙 맞추기**: 기기 렙(시작~끝 프레임, 원본 프레임 번호로 바꾼 것)이 물리적 렙의 기준점 프레임을 포함하면 같은 렙으로 본다.
  - 기기에서 세지 않은 물리적 렙은 "앱 렙 없음"으로 따로 센다.
  - 물리적 렙에 맞지 않는 기기 렙은 "가짜 렙"으로 따로 센다.
- **키마다·시점마다**:
  - TP = 키 발화 ∧ label error.
  - FP = 발화 ∧ ok.
  - 놓침(FN) = 발화 안 함 ∧ error.
  - TN = 발화 안 함 ∧ ok.
  - unsure = label unsure. 발화 여부와 함께 따로 세고, 비율 계산에서는 뺀다.
  - 판정 안 됨 = 게이트(측면·정면 게이트, 기준선 전 렙, 3D 판정 불가)로 그 키를 판정할 수 없었던 렙. 따로 센다.
  - 비율: PPV = TP/(TP+FP), 검출률 = TP/(TP+FN), ok 렙 오경보율 = FP/(FP+TN). Wilson 95% CI를 같이 낸다.
- **상대 키**는 절대 라벨(주)과 상대 라벨(`*_rel`, 보조) 둘 다로 계산한다. 대상은 squat_no_lockout, pushup_no_lockout, pushup_shallow, squat_shallow다.
- **끈 6개 키 판단 기준**(내 제안, 승인 아님):
  - **다시 켜기**: 다음을 모두 만족한다.
    - 판정된 렙에서 PPV ≥ 0.7.
    - ok 렙 오경보율 ≤ 5%.
    - 그 오류가 실제로 있다(검출률을 잴 수 있음).
  - **끈 채로 두기**: PPV < 0.5이거나 ok 렙 오경보율 > 10%.
  - **다시 정의**: 다음 중 하나다.
    - 오류는 실제로 자주 있는데 키가 다른 원인(시점·게이트·상대 정의)으로 울리거나 놓친다.
    - 절대 기준이 필요하다.
  - 렙 수가 적으면 CI와 함께 "근거 약함"으로 적는다.
- **오염 분석**(rc1 도출에 Exercise3D P1을 쓴 규칙):
  - P1 렙 가운데 그 기준을 error로 단 렙의 수를 센다.
  - 그 렙을 빼고 사전 등록 규칙(출처별 P99/P1, n ≥ 20, 가장 느슨한 값)으로 Ex3D P1 출처 분위수와 최종 T를 다시 계산한다.
  - 결정 출처가 바뀌는지, T가 얼마나 움직이는지 보고한다.
  - unsure 렙은 남겨 둔 계산과 뺀 계산을 둘 다 낸다.
