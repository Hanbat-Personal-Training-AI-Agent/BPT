# 스쿼트 무릎 모임을 발 방향 기준으로 다시 정의 — 사전 등록 (ai/valgus-foot-dir, 2026-10-22)

## 0. 이미 본 것 (정직하게)
- `rules_calib.md`의 현재 무릎 간격비 오경보(Fit3D 90% / 공개 63% / Ex3D 29%, 3D 기준 1.0)와 rc1 0.224, 조정 피험자 모캡 간격비 0.81–0.89.
- 기기 에이전트 관찰: 27–34° 사선이 "정면"으로 분류되고 그 시점에서 2D 간격비가 0.45–0.8.
- 발 방향 지표(아래 V1·V2)의 값은 어느 데이터에서도 보지 않았다.

## 1. 데이터와 경로 (rules-calib와 같음)
- 2D: RTMPose-m Halpe26(공개·Exercise3D = pose-replay CSV, Fit3D = 실험 A npz). 발: 20/21 왼/오 엄지발가락, 24/25 왼/오 뒤꿈치.
- 3D: 원래 MotionAGFormer-XS, Python 앱 경로(LiveMotionAGFormer + Pose3DConstraints, 공개·Ex3D) / Fit3D 캐시(L5) + 제약. 위 방향: 공개·Ex3D 카메라 −y, Fit3D 실제 중력(rules-calib 주 분석과 같음).
- 렙 구간: 공개·Ex3D는 같은 pose-replay JSON(앱 2D 상태기계), Fit3D는 rep_ann. 판정 가능 렙 = 렙 프레임 ≥50%가 ok/partial_3d.
- 정상 렙: Fit3D 전부, Ex3D 전부, 공개는 good + AI normal + form_status ok. 도출 = 조정(Fit3D s03–s05, 공개 조정, Ex3D P1), 평가 = held-out(Fit3D s07–s11, 공개 held-out, Ex3D P2·P3).
- 렙 창: 현재 간격비와 같다 — 엉덩이가 가장 낮은 프레임(2D hipY 최대)부터 렙 끝까지. 두 다리 중 나쁜 쪽.

## 2. 정의
기호: 같은 쪽 발목 A, 무릎 K, 뒤꿈치 H, 엄지발가락 T, 반대쪽 발목 A'. 관절 신뢰도 ≥ 0.3(앱 `minJointConfidence`, 발은 `footMinConfidence`).

- **V2 (주, 3D + 2D 발 방향) — 발 평면에서 무릎이 안쪽으로 벗어난 정도**
  - 발 방향 f(수평, 3D): 2D 뒤꿈치→엄지발가락 벡터 a = T − H의 화면 x 성분으로 발의 카메라 대비 회전을 구한다. 약원근 가정: 화면 1 px = 1/s(3D 단위), s = 세트의 중앙값 |엉덩이−발목|₂D / |엉덩이−발목|₃D,xy(두 다리). 발 길이 사전값 L = 0.6 × |정강이|₃D(뒤꿈치–엄지 ≈ 0.26 m, 정강이 ≈ 0.42 m). fx = aₓ/s(|fx| ≤ L로 자름), 깊이 성분 fz = ±√(L² − fx²), 부호는 몸 앞 방향(lr × u)의 카메라 z 성분과 같게. f = fx·x̂ₕ + fz·ẑₕ(수평면 = u에 수직).
  - 발 평면 = A를 지나고 u와 f를 담는 수직 평면. 안쪽 법선 n = normalize(u × f), A' 쪽을 향하도록 부호.
  - **V2 = ((K − A)·n) / |K − A|** (양수 = 무릎이 발 평면보다 안쪽 = 모임). 렙 지표 = 창 안 최대.
  - 임계값(미리 고정): **T = 0.10**(정강이의 10% ≈ 4 cm 안쪽, 문헌 값 아님 — 고정 사전값). 그리고 rules-calib 규칙으로 도출한 값(조정 정상 렙, 출처마다 p99, 가장 느슨한 값, n < 20 출처 제외).
- **V1 (보조, 2D만 — 앱이 지금 바로 잴 수 있음) — 무릎이 엄지발가락보다 안쪽**
  - 바깥 방향 o = sign(Aₓ − A'ₓ)(화면 x). **V1 = ((T − K)ₓ · o) / |K − A|₂D** (양수 = 무릎이 엄지발가락 세로선보다 안쪽). 렙 지표 = 창 안 최대.
  - 근거: 정면 관찰의 "knee medial to foot / great toe"(Ageberg 2010 KMFP, Crossley 2011 single-leg squat 평가) — 원문 수치 기준은 확인하지 않음.
  - 임계값: **T = 0**(무릎이 엄지보다 안쪽이면 울림, 고정), 그리고 위와 같은 규칙의 도출값.
  - 2D 뒤꿈치→엄지 벡터의 방향 자체는 V1에 쓰지 않는다: 정면에서는 발이 카메라 쪽을 향해 화면 방향이 원근(카메라 높이)에 지배되기 때문이다(그래서 방향은 V2에서 3D로 쓴다).
- **기준 비교**: 현재 간격비 3D(rules-calib 지표, T = 1.0 현재·0.224 rc1)와 앱 2D 간격비((lkₓ−rkₓ)/(laₓ−raₓ), T = 1.0; 앱은 정면 프레임에서만 잼 — 여기서는 모든 프레임에서 재고 게이트는 따로 적용).
- **모캡 참값(Fit3D만)**: joints3d_25의 발끝(17/18 왼, 19/20 오; 18·20 = 발끝)으로 f = 수평(발끝 − 발목). V2*를 같은 식으로 잰다. V2(XS+2D)의 렙별 오차 |V2 − V2*|를 보고한다.

## 3. 보고 (모두 시점 버킷별: 정면 / 사선 / 측면)
- 시점 버킷: 공개 = 라벨 `angle_deg`(front/diag/side), Ex3D = 카메라 각(≤40 측면, ≤75 사선, 그 밖 정면), Fit3D = 40–75° 사선뿐.
- 각 지표의 held-out 정상 렙 분포(p1/p5/p50/p95/p99)와 오경보율(Wilson 95%), 목표 ≤ 5%.
- 두 게이트: (a) 앱 게이트 그대로(렙 front_view_fraction ≥ 0.5 = 정면 렙), (b) 게이트 무시.
- 검출: 공개 held-out bad 클립 중 AI 합의 라벨 squat_knee_valgus(앱 게이트 통과 클립 수와 발화 수). 라벨 클립 < 5면 "검출 판단 불가"로 적는다.
- 판단 기준(미리): V2 또는 V1이 앱 게이트 정면 렙과 사선 렙 **모두**에서 오경보 ≤ 5%(고정 임계값)이고 간격비보다 낮으면 "발 방향 정의가 시점에 덜 민감함"이라고 적는다. 그 밖은 있는 그대로 적는다. 어느 쪽이든 채택 제안은 사람 검수 bad 데이터 전에는 하지 않는다.
