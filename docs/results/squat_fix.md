# 스쿼트 렙 카운트 일반화 — 공개 데이터 사람 단위 조정/검증 (트랙 squat-fix, D-T3-13–16)

앱 기본 = RTMPose-m COCO17, 사람 crop 입력(D-T3-10 재맞춤 켬), ready-pose 끔, 3D 없음. 수정 전 = integration/ai `68a3dc7` 규칙, 수정 후 = ai/squat-fix(`SquatEvaluator`만 바뀜, crop·다른 평가기 그대로).

**용어**
- 렙 정확도 = (정답 렙 − 놓친 렙) ÷ (정답 렙 + 더 센 렙), 세트 렙 수로 계산. 괄호 (−놓침 +추가).
- 관대 = 영상 시작·끝에 잘린 부분 렙(라벨 `partial`)을 세도 맞은 것으로 봄.
- 정확 = 렙 수가 정답과 똑같은 세트.
- 조정(tuning) / 검증(held-out) = `data/eval_sources/split.csv`의 사람(피험자·채널) 단위 분할(data-collect가 평가 전에 고정). **규칙은 조정 세트만 보고 정했고, 검증은 마지막에 한 번만 봄.**
- unknown = 평가기가 상태(top/descending/bottom/ascending)를 못 정한 프레임.

측정: 영상마다 Core ML RTMPose-m으로 키포인트를 한 번 뽑고(Mac pose-replay, heavy 락 영상 단위), 규칙은 `pose-replay --keypoints-dir`로 재생. 렙 라벨이 합의된 스쿼트 세트만(조정 72, 검증 81).

## 1. 놓침 원인 진단 (조정 세트)

| 원인 | 근거 (조정 72세트) |
|---|---|
| **경계 사이 정지 → `unknown`으로 강제 전이** | unknown 프레임 4,747개 중 다리 신뢰도 부족은 **25.5%뿐**. 나머지는 관절이 다 보이는데 깊이가 top(0.10)·bottom(0.22) 사이이고 프레임당 움직임이 0.012 다리 길이보다 느린 프레임 — 8프레임 이어지면 상태 기계가 `unknown`으로 넘어가고 `unknown → top`은 렙을 끝내지 않음. 천천히 일어서거나 중간에 멈추는 사람마다 렙을 잃음 |
| **선 자세 기준선이 낡음** | 기준선 = 첫 신뢰 프레임의 엉덩이 높이, 이후 `top`일 때만 낮아짐. 첫 프레임 오검출(yt_4FV_oEgDkX0_4: 엉덩이 35 px 위) 또는 세트 중 서는 높이가 바뀜(subject_002 good side: +57 px = 0.15 다리) → 서 있어도 깊이 > 0.10이라 `top`이 안 됨 → 세트 내내 `bottom` |
| **무릎을 끝까지 안 폄** | top은 무릎 > 145°도 요구. subject_011 good side는 렙 사이 무릎 최대 144–148° → 렙이 합쳐짐 |
| 먼 다리 신뢰도 부족(측면) | 6관절 모두 ≥ 0.30 요구. yt_WysdJhfVL3E_1은 6관절 다 보이는 프레임 21%, 가까운 다리만이면 98% |
| crop 재맞춤(D-T3-10) | 조정 측면 Mendeley 19세트: 재맞춤 끔 42.1% vs 켬 43.0% — 조정 데이터에서는 손해 없음 |
| 얕은 스쿼트 | 수정 후에도 남는 큰 놓침은 subject_008 bad(얕게, 21렙) 정도 — 깊이 범위가 다리 0.25 미만 |

## 2. 고친 것 (모두 플래그, 기본 켬)

| 플래그 | 내용 |
|---|---|
| `holdStatusThroughUnknown` | 근거 없는 프레임(경계 사이 느린 움직임, 또는 30프레임까지의 다리 신뢰도 부족)은 현재 상태에 투표 → `unknown`으로 강제 전이 안 됨 |
| `nearLegFallback` | 두 다리가 다 안 보이면 엉덩이·무릎·발목이 다 보이는 한쪽 다리로 측정 |
| `rebaselineStraightLegFrames = 30` | `top`이 아닌데 무릎이 30프레임(1초) 연속 펴져 있으면 지금 엉덩이 높이를 선 자세 기준선으로 |
| `heightRepSignal`, 범위 0.25 | 두 번째 렙 신호 = (발목 y − 엉덩이 y) ÷ 최근 90프레임 최장 다리 길이, `PushUpHeightCounter` 재사용(최근 90프레임 범위, 위 0.70 / 아래 0.35, 15프레임 이상). 렙 수 = max(상태 기계, 높이) — 푸시업 D-T3-11과 같은 방식 |

- **기각**: "근거 없는 프레임은 아예 투표 안 함"(15 fps 복제 프레임에도 하강 연속을 유지) — 조정 95.0%로 더 높았지만 흔들림 합성(m)에서 서 있는 상태 +1렙(bob 10%) → 회귀 조건 위반. crop 재맞춤 수정(히스테리시스 등) — 조정 데이터에서 재맞춤이 손해를 안 봐서(위 표) 손대지 않음.
- 되돌리기: 플래그 네 개를 끄면(`--squat-hold off --squat-near-leg off --squat-rebaseline 0 --squat-height off`) 조정 72세트 렙 수가 수정 전과 세트별로 같음(확인함).

## 5. iPhone 키포인트
- iPhone 17 상태가 이 트랙 내내 CoreDevice "unavailable"(무선, 잠김·절전 추정) → `run_pipeline.sh`로 기기 키포인트를 못 뽑음. 바뀐 것은 평가기뿐이고 포즈 단계(`RTMPoseCropTracker.estimate`)는 그대로라, 기기 키포인트가 Mac과 같다는 기존 확인(D-T3-05 39/39, D-T3-10 39/39)이 유지됨. 남아 있던 iPhone s 키포인트(Exercise3D squat_0000 cam1)는 수정 전후 10/10 그대로.
- 남은 일: 폰이 연결되면 `scratchpad/sq/dev/clips`(조정 세트 12개, 720p)로 `BENCH_DUMP=1` → 같은 규칙 재생.

## 6. 한계
- 라벨은 AI 2패스 합의(사람 검수 없음). Mendeley는 15 fps를 복제해 30 fps, 역광·블러.
- 높이 신호는 서 있다가 바를 바닥에서 드는 동작도 렙으로 봄(Fit3D 세트 밖 +1~3).
- YouTube 검증 측면·정면은 세트가 짧고(정답 1–4렙) 수가 적어 70%대 — 놓친 세트 몇 개가 크게 흔듦.
