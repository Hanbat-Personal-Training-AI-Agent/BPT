# Offline bone target continuity candidate — 2026-11-02

One predeclared engineering candidate was implemented and evaluated on the same three reused native development captures. It reduces the discrete prior→session target transition in these arrays, **does not resolve raw direction amplification**, and is **not adopted**. There is no GT accuracy, actual-movement suppression, contact-motion or coaching false-negative validation. A smaller numerical peak alone does not establish a correct pose or justify activation.

## Frozen protocol and implementation

[Protocol](bone_target_continuity_protocol_20261102.md) and [BoneTargetContinuity.swift](../../scripts/wrist_observation/BoneTargetContinuity.swift) were committed as **e376f90 before candidate statistics were computed**. No sweep or second parameter setting was run. Positive target proportions are normalized by their sum, then linearly filtered with `alpha=1-exp(-ln(2)*source_dt/0.2)`. Half-life0.2s and long-gap reset>1.0s are fixed, unvalidated engineering choices. Changing source label prior→session keeps the filter continuous; changing profile epoch initializes at the new profile immediately. Uniform target scaling has no meaning to the downstream solver, which computes scale separately for each raw frame.

The module accepts only targets, explicit source timestamp, target source label, profile epoch and tracking-valid flag. It accepts **no joint positions, velocity, direction, GT or goal angle**. It returns source, original targets, normalized original shape, filtered shape, status and alpha. No source time means unsupported, not assumed30fps. Invalid/nonpositive/nonfinite targets, missing/nonfinite/negative time, nonmonotonic time, missing profile epoch or tracking invalidation clear state and explicitly return unsupported. Public `reset()` clears state; profile epoch/key-set change and gap>1.0s initialize directly from the new shape with an explicit reason. Caller must assign a new epoch/reset whenever person/session/profile ownership changes; this module cannot infer identity. New profile data never blend with the previous epoch. These reset cases can produce a discontinuity by design and are not certified complete/normal exercise observations.

All code lives under `scripts/wrist_observation`. It is not registered with Runner, not called from Camera, and has no app feature/default switch. Existing runtime, model, original thresholds, original rep boundaries and reports are untouched. Actual Swift offline replay uses original raw arrays and original per-frame target dictionaries. A second unchanged full constraint instance receives the filtered target proportions through its calibration-target argument solely as a target-injection mechanism; **these are not a new personalized or clinically calibrated profile**. The true target source remains separately recorded as prior/session. Original target history is generated by the baseline independently of candidate output. Nothing is fed back into original targets or future raw predictions.
