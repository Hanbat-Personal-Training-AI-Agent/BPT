# Scoped composite criteria v1 (scripts only)

`evaluate(request: dict) -> dict` in `engine.py` is a pure JSON-compatible evaluator. `json_contract.evaluate_json` additionally rejects duplicate JSON keys/nonfinite constants. There is no dynamic eval, arbitrary expression language, file/network/model access, product wiring or default target threshold. See `example.json` for a fully synthetic engineering profile. `catalog.py` explicitly limits versioned metric definitions/exercise applicability; no metric name aliases native shoulder–hip–knee to ExperimentalCoaching thorax8–hip–knee.

## Typed input

- Request: `exercise` (pushup/squat/barbell-row), explicit `variant`, `evaluation:{mode:causal|offline_declared,asOfPts}`, `observations:{id:Observation}`, `profiles:{id:Profile}`, and a criterion tree.
- Atom: `{type:atom,id,observation,profile?}`. Group: `{type:group,id,op:AND|OR,children:[Atom|Group],pairing?:{sidePolicy:same_selected_side|bilateral,temporal:simultaneous|same_window_summary}}`. IDs must be unique. Groups never infer a profile or invert a warning key.
- Observation identity: `metricId,metricVersion,definitionHash,unit,coordinate,aggregation:sample|max|min|rom|delta`. `rawValue`, `correctedValue`, `available`, `blockingReasons` and extra provenance stay intact. `samples` contain actual `sourceIndex,pts,rawValue,value,available,blockingReasons?,side,phase,view,flush?`.
- Scope: `sourceIdentity:{inputSha256,sourceCommit,modelSha256,epoch,clockId}`, `timeBasis:source_pts_seconds`, `startPts,endPts`, `side,selectedSide,phase,view`. Unknown source/phase/side/view does not become valid by matching numbers. Model-space angles are not ground/contact measurements. Anatomical left/right is retained in the metric identity; selected-side history is separate.
- Complete span evidence: `coverageComplete:true`, ordered exact `expectedSourceIndices`, `coverageEvidence:{phaseStartObserved:true,phaseEndObserved:true,membershipSource:<explicit provenance>}`. This is caller-provided evidence provenance, not independent discovery of occlusion. A native/deep interval adapter must separately preserve its inclusion policy and actual source membership; this kernel does not guess fps, remap clocks or invent endpoint frames.
- Support: explicit `requiredJointsSupported,trackingObserved,rawCorrectionChecked` and supplied finite nonnegative `maximumCorrectionDifference`; trunkInclineDeg additionally requires `gravitySynchronized:true`. Each sample with a blocking reason or failed raw/corrected check is excluded from supported evidence. Scores remain original numeric observations, not calibrated accuracy probabilities.
- Profile: full observation identity, `ruleId,exercise,variant,comparator:gt|gte|lt|lte|inside|outside`, finite `lower/upper` as relevant; `referenceKind:explicit_target|engineering_candidate|observed_first3`; mandatory `predicateMeaning:deviation|desired_match`, `revision,source,availableAtPts`, `applicability:{phase:[],side:[],view:[]}`, and `confirmation:{kind,at,reference,scope:<matching exercise/variant/rule/metric identity>}`. A boolean approval is insufficient. Profile hash is an integrity fingerprint, **not authenticated review authority**. Confirmation metadata is caller supplied, not a verified signature.
- observed_first3 additionally requires exactly three earlier references with unique IDs, repIndex1/2/3, strictly earlier sorted endPts, fully supported values, exact metric and source/side/phase/view context. Only `current−median(first3)` is compared. An equally wrong reference can yield zero change; that is not correctness. No later repetition/profile is learned into an earlier evaluation.
- Optional positive `sustainSeconds` requires explicit positive `maximumGapSeconds`. Duration uses actual PTS, consecutive source indices and matching context; missing samples/gaps/flush/side/phase/view changes never bridge time. A short/incomplete window cannot certify a negative sustained condition.

## Decisions and composition

Every atom retains original numeric/support evidence and produces `positive_evidence`, `negative_evidence`, `unknown` or `not_applicable`, with reasons. Positive means **the supplied predicate holds**. `predicateMeaning` says whether that is a desired match or deviation; reference interpretation remains scoped target / candidate / relative change. No output means whole-form normal, clinical validation, safety or model accuracy.

OR retains a supported positive despite another missing/unknown component, marks partial coverage and retains all component reasons. Conflicting **known** capture/phase/side/window contexts instead make the aggregate unknown while retaining each positive child, so a different clip cannot become the current warning. AND positive+unknown stays unknown. Missing/quiet/not-applicable are not negative evidence. Simultaneous AND requires an explicit pairing policy, identical input/source/model/epoch/clock/window/phase/view, selected-side compatibility and an intersection of actual supported positive `(sourceIndex,PTS)` samples. Explicit bilateral pairing permits left/right anatomical metrics from those same captured samples; it does not merge different selected-side histories. Two maxima occurring at different samples do not prove simultaneous conditions. Whole-span/min/ROM/delta predicates instead require explicitly declared same_window_summary and matching actual membership; they do not claim instantaneous coincidence. Nested groups propagate actual sample membership; missing membership cannot pass by comparing two nulls. A nested missing or incompatible scope never acquires a fabricated shared context.

Partial min/ROM/delta is unknown in either numeric direction: unseen extrema may reverse it. Partial max can retain a supported existential gt/gte exceedance; partial non-exceedance, bounded range or minimum claim is unknown. Sample-specific failed support does not erase a different actually supported max exceedance.

## Replay bridge and scope

`replay_adapter.frame_request` consumes exact `coaching_observation_evidence.v1` frame metrics, preserves each original metric, and uses pinned `replay_catalog_v1.json` metadata/source hashes. Camera torso and hip-line proxies explicitly retain camera-up/no-verified-ground semantics. Source definitions are checked, not renamed from anatomical literature. Unknown/mismatching metrics remain in output with reasons. Missing source-model proof is not filled from a guessed donor. No profiles are created, so real numeric observations remain descriptive and target criteria remain unknown/not-applicable. `summarize(path)` reads originals without mutation and splits genuine versus flush opportunities.

The catalog currently contains11 quantities, not all requirements for complete core3 posture. Image hip/shoulder rates, actual contact/grip, lumbar curvature and absolute depth targets are not implemented or inferred. This does not replace existing runtime warnings, A-engine relative comparisons, or the app's default rules. No model coordinates are modified.

## Independent native kernel

`ios/Runner/NativePose/Evaluators/CoachingCriteria.swift` implements the same pure dictionary API without calling Python. The package source symlink and Xcode source entry use the same file. `CoachingCriteria.evaluate([String:Any]) throws -> [String:Any]` checks JSON depth/size, criterion depth/node/ID budgets, native booleans and nonfinite values. JSON decimal numbers use their exact NSNumber string before Double conversion to avoid Foundation NSDecimalNumber conversion drift. Profile fingerprints match sorted compact Python JSON, including ASCII escaping and decimal formatting.

Generate synthetic full-output parity fixtures with `python -m scripts.coaching_criteria.generate_parity_fixtures`; `--check` detects stale outputs. `swift test --package-path ios/CalibrationEngineKit --filter CoachingCriteriaTests --jobs 2` checks every field and reason (numeric tolerance 1e-10), plus malformed/nonfinite/depth/node guards. Current 93 cases include nested OR/AND, clip/clock/side/membership conflicts, sustained qualifying-run membership, summary-only nested predicates, first3, overflow and decimal/Unicode fingerprints. These are contract tests, not measured exercise accuracy.

Sustained evidence only propagates samples belonging to contiguous positive runs that actually reach the supplied duration. A nested positive summary remains a summary through groups and cannot become instantaneous evidence at an outer simultaneous AND. Every finite input arithmetic subtraction used for predicate support is checked before decision. No runtime bridge, target loading, delivery, default activation or whole-form correctness follows merely from compiling the kernel.

## Default-off app diagnostic bridge

`CoachingCriteriaBridge` consumes the existing nine Codable ExperimentalCoaching metrics without loading profiles or thresholds. Camera attaches bounded `bpt.coaching-criteria-terminal.v1` summaries only under the existing opt-in flag and the existing terminal-evidence capture gate. Explicit bound error markers preserve enabled encoding/evaluation failures. Anatomical side is separate from selected side; not-side-view remains unknown. Two camera proxies remain explicitly unsupplied. Legacy rows without summaries remain readable; optional summaries must bind to the exact containing source/epoch/clock and exercise.

`python -m scripts.coaching_criteria.verify_native_bridge_replay INPUT --app-shaped --output RECEIPT` streams local existing JSONL evidence through the native app-shaped adapter and verifies metrics, state/reasons, source binding and original hashes against Python. Omit `--app-shaped` to retain exported proxy negative controls. See `docs/results/coaching_criteria_native_bridge_20261103.{md,json}` for the2398-frame receipts and iOS typecheck limits.
